# ReachAI 部署与运维手册

这份手册写给第一次部署 ReachAI 的运维和开发同学，一件事一节，照着做就行。用 Codex、Claude Code 帮你部署时，也请让它按本手册的命令执行（见最后一节）。

- 想先体验带演示 ERP 的完整效果：用 [10 分钟一键体验](../deploy/quickstart/README.md)。
- 想改 ReachAI 源码：用 `./dev.sh`，见 [开发与验证](development.md)。
- 想装一套给自己或团队用：看本手册。

## 1. 准备

| 项目 | 最低 | 推荐 |
| --- | --- | --- |
| CPU / 内存 | 2 核 4G（不开 Milvus） | 4 核 8G（开 Milvus） |
| 磁盘 | 20G 可用 | 50G 以上 |
| 系统 | 能装 Docker 的 Linux（x86_64 / arm64）、macOS、Windows 10/11 | Ubuntu 22.04 / Debian 12 / CentOS Stream 9 |
| 软件 | Docker 24+，docker compose 2.24+ | — |

- 服务器只需要对外开放一个端口（默认 8080），配了反向代理就只开 80 / 443。
- 机器要能访问镜像仓库 `ghcr.io`。国内服务器访问慢时，见「常见问题」里的镜像加速。
- 要让员工用 Codex / Claude Code 连 ReachAI，最好准备一个域名和 HTTPS 证书。

## 2. 安装

三种方式装出来的是同一套东西，都只需要一条命令。安装目录里只有几样东西：

```text
reachai/                 （root 安装在 /opt/reachai，其他用户在 ~/reachai）
├── reachai.env          配置（含自动生成的密码，权限 600）
├── docker-compose.yml   服务编排，一般不用改
├── data/                密钥 secrets.properties、知识库原件、Skill 包
├── mysql/               自带 MySQL 的数据
├── backups/             reachai backup 的备份
└── reachai              运维命令（已链接到 /usr/local/bin/reachai）
```

### 2.1 Linux 服务器（给团队用）

```bash
curl -fsSL https://raw.githubusercontent.com/w8123/EnterpriseAgentFramework-dev/dev/deploy/install.sh | sudo bash -s -- --server
```

安装过程会问两个问题：访问端口、浏览器访问地址（有域名就填域名）。没有 Docker 时会提示自动安装。最后屏幕上会打印访问地址、管理员账号 `admin` 和随机生成的初始密码。

常用参数（加在 `--server` 后面）：

| 参数 | 作用 |
| --- | --- |
| `--url https://reachai.example.com` | 直接指定访问地址，不再提问 |
| `--port 8080` | 访问端口 |
| `--with-milvus` | 同时装 Milvus，知识库才能做向量检索（多占约 1.5G 内存） |
| `--external-db` | 用你自己的 MySQL（库要提前建好，空库即可） |
| `--version v0.1.0` | 固定镜像版本，默认 `dev` 跟随最新开发版 |
| `--registry <地址>` | 换镜像仓库（国内加速） |
| `--dir /data/reachai` | 换安装目录 |
| `--yes` | 不提问，全部用默认值 |

### 2.2 自己电脑试用（Linux / macOS）

```bash
curl -fsSL https://raw.githubusercontent.com/w8123/EnterpriseAgentFramework-dev/dev/deploy/install.sh | bash
```

本机模式只监听 `127.0.0.1`，打开 http://localhost:8080 。和服务器模式的区别只在默认配置：ReachAI 可以访问本机和内网里的业务系统（业务系统在本机时，在 ReachAI 里填 `http://host.docker.internal:端口`）。

macOS 需要先装好并打开 [Docker Desktop](https://www.docker.com/products/docker-desktop/)。

### 2.3 Windows（Docker Desktop）

先装好并打开 Docker Desktop（需要 WSL2），然后在 PowerShell 里运行：

```powershell
irm https://raw.githubusercontent.com/w8123/EnterpriseAgentFramework-dev/dev/deploy/install.ps1 | iex
```

装在 `%USERPROFILE%\reachai`。要用服务器模式或带参数，先下载再运行：

```powershell
irm https://raw.githubusercontent.com/w8123/EnterpriseAgentFramework-dev/dev/deploy/install.ps1 -OutFile install.ps1
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1 -Mode server -Port 8080 -Url https://reachai.example.com -WithMilvus
```

装好后在安装目录用 `.\reachai.ps1 status | doctor | logs | restart | backup | upgrade` 管理，用法和 Linux 的 `reachai` 命令一样。

### 2.4 已经会用 Docker

```bash
mkdir reachai && cd reachai
base=https://raw.githubusercontent.com/w8123/EnterpriseAgentFramework-dev/dev/deploy
curl -fsSLO $base/docker-compose.yml -fsSLO $base/milvus-embedEtcd.yaml
curl -fsSL $base/reachai.env.example -o reachai.env
vi reachai.env          # 填管理员密码和两个数据库密码
docker compose --env-file reachai.env up -d --wait
```

### 2.5 没有外网 / 镜像下载不了

在能上网的机器上导出镜像，拷到服务器上导入，再用 `--no-pull` 安装：

```bash
# 能上网的机器
docker pull ghcr.io/w8123/reachai-server:dev
docker pull ghcr.io/w8123/reachai-web:dev
docker pull mysql:8.0
docker save ghcr.io/w8123/reachai-server:dev ghcr.io/w8123/reachai-web:dev mysql:8.0 | gzip > reachai-images.tar.gz
# 服务器（同时把仓库的 deploy 目录拷过去）
docker load < reachai-images.tar.gz
sudo bash deploy/install.sh --server --no-pull
```

也可以在源码目录里现场构建镜像：`bash deploy/install.sh --build`（第一次约 10 分钟）。

## 3. 第一次登录

1. 打开安装结束时打印的地址，用 `admin` 和初始密码登录。初始密码也写在 `reachai.env` 的 `REACHAI_BOOTSTRAP_ADMIN_PASSWORD`。
2. 左侧点「开始使用」，按四步走：接入模型 → 接入业务系统 → 发布给员工 → 员工连上自己的 AI 工具。
3. 同一页的「系统体检」会列出服务、密钥、管理员密码、Milvus、Docling 的状态，有问题会写清楚怎么修。

## 4. 接入业务系统

- Java（Spring Boot）系统：引入 ReachAI starter，自动把接口同步过来。步骤见 [SDK 与 Embed Chat 快速参考](integration.md)，完整例子见 [芋道 ERP 接入 ReachAI 实施步骤](guides/芋道ERP接入ReachAI实施步骤.md)。
- 其他系统：在「业务系统」里上传 OpenAPI（Swagger）文档，或填文档的 URL。
- 业务系统和 ReachAI 在同一台机器上时，地址填 `http://host.docker.internal:端口`；在内网其他机器上时，要在 `reachai.env` 里打开 `RUNTIME_HTTP_EGRESS_ALLOW_PRIVATE=true`（本机模式默认已打开），然后 `reachai restart`。

## 5. 配域名和 HTTPS

ReachAI 只需要把整个站点反向代理到 `127.0.0.1:8080`。

1. 在 `reachai.env` 里把 `REACHAI_BIND` 改成 `127.0.0.1`（只让本机的 Nginx 访问），`REACHAI_PUBLIC_URL` 改成 `https://你的域名`。
2. 运行 `reachai restart` 让配置生效。
3. 配 Nginx（宝塔：网站 → 添加站点 → 反向代理到 `http://127.0.0.1:8080`，再申请 SSL 证书）：

```nginx
server {
    listen 443 ssl http2;
    server_name reachai.example.com;
    ssl_certificate     /path/fullchain.pem;
    ssl_certificate_key /path/privkey.pem;
    client_max_body_size 100m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # 对话是流式输出，不能缓冲
        proxy_buffering off;
        proxy_read_timeout 600s;
    }
}
```

4. 运行 `reachai doctor`，「访问」一栏应显示 `https://你的域名 可以打开`。

## 6. 日常运维

| 要做的事 | 命令 |
| --- | --- |
| 看各服务状态 | `reachai status` |
| 体检（出问题先跑它） | `reachai doctor` |
| 看日志 | `reachai logs control`，加 `-f` 持续看；服务名：model knowledge capability runtime control web mysql milvus |
| 重启全部 / 某个服务 | `reachai restart` / `reachai restart runtime` |
| 改了 reachai.env | `reachai restart`（会重新创建容器，让新配置生效） |
| 停止 / 启动 | `reachai stop` / `reachai start` |
| 开启 Milvus | `reachai.env` 的 `COMPOSE_PROFILES` 改成 `mysql,milvus`，再 `reachai start` |

日志由 Docker 自动轮转（每个服务最多 100MB），不用手动清理。

## 7. 备份与恢复

**必须一起备份的两样东西：数据库和 `data/secrets.properties`。** 密钥文件丢了，已保存的模型 API Key、Workflow 凭据就解不开了。

```bash
reachai backup                                    # 生成 backups/reachai-时间.tar.gz，自动保留最近 10 份
reachai restore backups/reachai-20261028-140334.tar.gz
```

- 备份包里有数据库导出、密钥文件、`reachai.env` 和知识库原件，权限是 600，请再拷一份到别的机器。
- 用自己的 MySQL 时，`reachai backup` 只备份密钥和配置，数据库请用你们平时的方式备份。
- 建议每天定时备份：`crontab -e` 加一行 `0 3 * * * /usr/local/bin/reachai backup >/dev/null 2>&1`。

## 8. 升级

```bash
reachai upgrade            # 跟随当前版本标签（默认 dev）拉最新镜像
reachai upgrade v0.2.0     # 升到指定版本
```

升级会自动：备份 → 下载新镜像 → 重启 → 体检。新版本如果带数据库升级脚本，发布说明里会写明，需要按 [SQL 说明](../sql/README.md) 执行（执行前已经有备份）。升级后有问题，用 `reachai restore` 回到升级前的备份，并在 `reachai.env` 把 `REACHAI_VERSION` 改回原来的版本。

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 镜像下载失败 / 很慢 | 国内服务器可以给 Docker 配镜像加速，或安装时加 `--registry <加速地址>`；也可以按 2.5 离线导入 |
| 安装卡在「启动 ReachAI」 | `reachai doctor` 看哪个服务没起来，再 `reachai logs <服务>`；最常见是内存不够 |
| 服务反复重启、doctor 提示被系统杀掉 | 内存不够。关掉 Milvus，或在 `reachai.env` 调小 `REACHAI_JAVA_OPTS_*` 里的 `-Xmx`，或给机器加内存 / 开 swap |
| 浏览器打开是 502 | Control 还在启动（首次约 1 分钟），稍等；一直 502 就看 `reachai logs control` |
| 模型测试失败 | 页面会写明原因：Key 不对、余额不足、地址连不上等，按提示到模型中心修改 |
| 知识库提示 Milvus 没连上 | 按 6 节开启 Milvus；不用知识库检索可以忽略 |
| 只能导入 txt / md / csv | 需要 Docling 解析 PDF、Word；在 `reachai.env` 配置 `REACHAI_DOCLING_ENABLED=true` 和 `REACHAI_DOCLING_BASE_URL` |
| 调用业务系统提示连不上 | 检查「业务系统」里登记的地址；在本机用 `host.docker.internal`，内网要开 `RUNTIME_HTTP_EGRESS_ALLOW_PRIVATE` |
| 员工的 Codex / Claude Code 连不上 | `REACHAI_PUBLIC_URL` 必须是员工电脑能打开的地址（不能是 localhost），并且建议是 https |
| 忘了管理员密码 | 初始密码在 `reachai.env`；改过又忘了，请让另一位平台管理员在「身份与权限 → 账号与权限」里重置密码 |

## 10. 卸载

一条命令，会先问你要不要保留数据：

```bash
reachai uninstall
```

- **保留数据**（直接回车）：删除容器、网络、ReachAI 镜像和 `reachai` 命令，数据库、密钥、上传的文件和备份留在安装目录。以后重新运行 `install.sh --dir <安装目录>` 就能接着用，管理员密码不变。
- **全部删除**（回答 n，再输入 `delete` 确认）：在上面的基础上，再删掉数据和整个安装目录，以及只给 ReachAI 用的 MySQL / Milvus / Redis 镜像（别的容器还在用的会保留）。删除前会问要不要先导出一份备份，导出的文件放在安装目录的上一级，例如 `/opt/reachai-20261030-003020.tar.gz`。

不想回答问题时（比如写在脚本里）：

```bash
reachai uninstall --keep-data --yes   # 保留数据
reachai uninstall --purge --yes       # 全部删除，不导出备份；要备份就再加 --backup
```

找不到 `reachai` 命令时，用安装脚本卸载，效果一样：`bash install.sh --uninstall`（装在别的目录时加 `--dir <安装目录>`）。

Windows：在安装目录里运行 `.\reachai.ps1 uninstall`，也可以加 `-KeepData` 或 `-Purge`，以及 `-Yes`。

说明：

- MySQL、Milvus 在容器里写出的文件属于容器用户，普通用户直接删不掉，卸载会借一个容器把它们删干净，不需要 sudo。
- 用的是自己的 MySQL（`--external-db`）时，卸载不会碰你的数据库，需要的话自己删掉 `reach_ai` 库。
- 只删除 ReachAI 自己装的东西。Docker 本身不会卸载，因为别的程序可能也在用。
- ReachAI 不会改系统环境变量和 shell 配置文件，卸载后不会留下配置。

## 给 AI 编程工具的部署说明

让 Codex、Claude Code 帮你部署或排障时，请让它遵守：

1. 只用本手册里的命令：`deploy/install.sh`（Windows 用 `deploy/install.ps1`）、`reachai doctor / logs / restart / backup / upgrade`。
2. 只改 `reachai.env`，不改 `docker-compose.yml`，不自己写新的编排文件或启动脚本。
3. 改动数据库前先 `reachai backup`；不在已有库上重跑 `sql/initV2.sql`。
4. 不删除 `data/` 和 `mysql/` 目录（要卸载就用 `reachai uninstall`），不把 `reachai.env`、`secrets.properties` 的内容贴到聊天或提交到 Git。
5. 出问题先跑 `reachai doctor`，按它的提示处理，再看 `reachai logs <服务>`。
