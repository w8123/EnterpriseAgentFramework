# 没有 SDK：导入 OpenAPI

> 适合：改不了业务系统代码，但有 Swagger / OpenAPI 文档的开发者。读完你会把业务系统的 HTTP 接口导入 ReachAI。

## 做完你会得到什么

业务系统的 HTTP 接口出现在 ReachAI 的「业务能力」里，可以编进 Workflow、交给 Agent 调用。

## 和 SDK 接入有什么区别

| | SDK 接入 | OpenAPI 导入 |
| --- | --- | --- |
| 要改业务代码 | 要 | 不要 |
| 接口说明从哪来 | 代码里的注解，写给 AI 看 | OpenAPI 文档里的 summary、description |
| 员工身份 | 身份桥还原成业务登录用户，数据权限自动生效 | 由你配置的鉴权方式决定，通常是一个固定的服务账号 |
| 接口变了怎么办 | 业务系统重启自动同步 | 重新导入文档 |

**OpenAPI 导入拿不到员工本人的身份**。如果业务数据有按人隔离的权限，只用 OpenAPI 导入的话，AI 看到的是服务账号能看到的全部数据。这种情况下要么只开放不敏感的查询，要么接 SDK。

## 开始前你需要

- 业务系统导出的 OpenAPI 文档：`.json`、`.yaml` 或 `.yml`，最大 5 MB。Swagger 2 和 OpenAPI 3 都可以。
- ReachAI 能访问业务系统的接口地址。

## 第 1 步：新建项目，选 OpenAPI 导入

左侧「接入与能力 → 项目管理」，点 **接入项目**，接入方式选 **OpenAPI 导入**。填写项目名称、编码、业务系统地址，上传文档。

文档内容保存在平台数据库里，平台不会去读你服务器上的源码或文件。

## 第 2 步：配置接口鉴权

在「业务能力 → HTTP API」里选中这个项目，打开 **接口鉴权**，按业务系统的要求填写调用时带的鉴权信息（比如固定 Token 或 API Key）。密钥只保存在平台服务端，页面上不会再显示。

## 没有完整文档：一个个添加

只有几个接口、或者没有 OpenAPI 文档时，在「业务能力 → HTTP API」选中项目后点 **添加 API**，可以：

- 粘贴 OpenAPI / Swagger 2 的 JSON 片段（Swagger 2 会自动转换）；
- 粘贴一条 `curl` 命令；
- 手工填表（方法、路径、参数）；
- 复制弹窗里的提示词交给你的 AI，让它扫描业务代码后通过平台连接批量上传（一次最多 200 个）。

手工添加的接口不会被之后的全量重新导入覆盖；同一个「方法 + 路径」再次添加会更新原来那条。

## 第 3 步：挑选并核对接口

导入后，接口会出现在「业务能力」里。逐个检查：

- 名称和说明是否写清楚了能做什么。OpenAPI 文档里 summary 太简略时，AI 很难选对接口，建议先补文档再导入。
- 副作用是否正确：GET 一般是只读，POST / PUT / DELETE 会被当作写操作。
- 试调用一次，看返回结构。

见 [核对业务能力](capabilities.md)。

## 接口变了怎么办

- 文档内容更新：在项目来源的「同步与发现」里重新导入。
- 换一份文档：项目详情点「编辑」，重新上传。

重新导入后，有变化的接口会显示「来源变化」，确认后才会替换线上使用的版本。

## 遇到问题

**上传提示格式不对。** 先用 Swagger Editor 之类的工具检查文档能否正常解析，确认大小不超过 5 MB。

**Java / Spring 系统能不能直接扫 Controller？** 平台已经不再扫描源码。Spring 系统用 [Java Starter](java-starter.md)，Starter 可以发现 Spring MVC 接口，拿到的参数和响应结构更完整。
