# 开发者常见问题

> 适合：接入过程中遇到问题的开发者。按「卡在哪一步」查找。

先试一下最快的办法：让你的 AI 用 `reachai_doctor` 检查项目（见 [交给我的 AI](ai-tool-handoff.md#ai-能帮你做的检查)），或者打开项目接入工作台看哪一项没通过。

## 注册和同步

**业务系统启动后，工作台显示「后端 SDK 未注册」。**
看业务系统启动日志里 ReachAI 相关的报错：

- 连不上注册地址：业务系统所在机器能否访问 ReachAI？地址不能是会重定向的地址，SDK 遇到重定向会直接失败。
- 令牌无效：令牌已过期（72 小时）或已经用过。到项目详情重新生成。
- 项目编码不一致：配置里的编码要和平台上完全一致。

**注册过一次，换了台机器（或容器重建）后又要令牌。**
长期凭据保存在本机凭据文件里。容器部署时把凭据文件放在持久卷里；多实例时让所有实例共用同一份受保护的凭据。

**方法同步上来的数量不对。**
检查扫描范围（Java 的 `scan-packages`）是否覆盖了方法所在的包，方法所在类是否被框架管理（Spring Bean）。同一系统里方法名重复，SDK 会拒绝同步，日志里会写出重名的方法。

**业务代码改了，平台上没变化。**
业务系统要重新部署启动才会同步。同步后有变化的方法显示「来源变化」，要在业务能力里确认接纳。

## 调用

**调用返回「需要有效的业务用户身份」或 403。**
这个调用没有带员工身份。下面这些地方本来就不带员工身份，声明了 `businessIdentityRequired = true` 的方法会被拒绝：

- 业务能力里的「试调用」（项目测试身份）；
- Workflow Studio 的「只读试运行」（项目测试身份）；
- Agent 调试页（你的平台账号）；
- 自动化任务（自动化服务账号）。

在业务页面的助手里、或员工自己的 AI 工具里用真实员工账号验证。

**调用返回 401。**
业务系统的登录拦截挡住了 `/reachai/**`。放行这条路径，见 [业务身份桥](business-identity.md#放行-reachai-路径)。

**业务方法里拿不到当前用户。**
身份桥建立的上下文不是业务代码读取的那个。多租户框架通常还有自己的租户上下文，也要设置。参考芋道的 `YudaoReachAiSecurityBridge`。

**业务系统返回了错误，ReachAI 却当成功。**
业务系统用 HTTP 200 + 业务错误码返回错误时，确认包装格式能被识别；最稳妥的做法是在方法里直接抛异常。

## 助手（嵌入）

**页面右下角没有助手。**
浏览器控制台看报错：SDK 脚本或样式没加载、`apiBase` 写错、挂载的容器不存在。

**换令牌返回 401。** 业务后端没拿到登录态，检查请求有没有带 Cookie 或认证头。

**换令牌返回 403。** 页面地址不在 Agent 嵌入设置的来源白名单里（协议、域名、端口都要一致），或员工角色不在 Agent 的使用范围里。

**升级 ReachAI 后助手 403。** 新版要求换令牌请求正文签名，业务系统里的 SDK 要升级到同版本。

**助手回答「我做不了这件事」，但业务系统明明有这个功能。**
助手只能用 Agent 上挂了的 Workflow。业务方法在目录里，不代表已经编成 Workflow 并挂到 Agent 上。

## 员工的 AI 工具（MCP）

**员工生成连接时看不到这个系统。** MCP 服务是否已发布、「员工可用」是否打开、员工角色是否有调用权限。见 [发布 MCP 服务给员工](publish-mcp.md)。

**员工调用写操作没反应。** 写操作提交后在等审批，让管理人员到「写操作审批」处理。

## 模型和知识库

**Agent 回答报错。** 运行中心看这次运行的错误。常见是模型 Key 失效、限流、上下文太长。

**知识库上传后一直解析中。** 文档解析服务没开。平台管理员在「开始使用 → 系统体检」查看。

## 还没解决

- 在运行中心找到这次运行，看具体哪一步失败、错误原文是什么。
- 平台侧问题见 [平台常见问题和排查](../admin/troubleshooting.md)。
- 已知的限制和未完成事项见 [当前边界](../status.md)。
