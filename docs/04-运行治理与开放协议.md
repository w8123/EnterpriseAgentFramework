# 运行治理与开放协议

## 定位

运行治理负责回答“谁在什么时候、以什么身份、调用了什么能力、为什么被允许或拒绝、出了问题如何复盘”。开放协议负责把平台内的 Tool、Capability 和 Agent 安全暴露给外部 IDE、业务系统和远程 Agent。

## 当前已落地

### 执行入口

| 入口 | 用途 | 代码 |
| --- | --- | --- |
| `/api/runtime/agents/execute`、`/api/runtime/agents/execute/detailed` | Agent Supervisor 同步执行和详细执行 | `RuntimePublicController` |
| `/api/runtime/agents/execute/stream` | Agent Supervisor SSE 执行；输出规划/Workflow 步骤、回答、UI 请求和完成事件 | `RuntimePublicController`，由 Control 无缓冲转发 |
| `/api/runtime/agents/sessions/{sessionId}` | 清理 Agent Supervisor 会话记忆 | `RuntimePublicController` |
| `/api/v1/agents/{key}/chat` | 面向业务方的 Agent key 调用 | `reachai-control-service` `ControlRuntimePublicController` -> `reachai-runtime-service` |
| `/gateway/catalog`、`/gateway/agents/{key}/chat` | AI Gateway 目录和调用入口 | `reachai-control-service` `ControlRuntimePublicController` -> `reachai-runtime-service` |

Agent 执行统一进入 `RuntimeAgentExecutionService`，解析当前 ACTIVE Agent 配置版本及 Workflow-as-Tool 白名单，再交给 `SupervisorRuntimeAdapter`。旧的 Lightweight Chat `/api/chat` 主路径已删除；模型调试使用 Model Gateway 结构化流 `POST /model/chat/stream/events`（旧文本流 `/model/chat/stream` 已删除），业务嵌入对话继续使用 `/api/embed/chat/sessions/{sessionId}/messages/stream`，两者不属于 Agent 调试模式。

### Trace 与 RunOps

RunOps 按“一个根事实 + 三类子事件”组织：

- `runtime_run`：每次用户或外部入口执行一行，是最近运行、KPI、趋势、诊断、对比和回放的唯一根事实。Agent 零 Workflow 直接回答也必须存在 Run。
- `runtime_trace_span`：Supervisor、PLAN、REPLAN、Workflow-as-Tool、Workflow Graph 节点和 LLM 等父子 Span。
- `runtime_tool_call_log`：底层 Tool / Capability 调用、耗时、状态、输入输出摘要和召回轨迹。
- `runtime_guard_decision_log`：Guard 的允许、拒绝和确认决策。

Tool 与 Span 都不是根运行类型，不能再通过“是否存在 Tool 日志”推断一次运行。根 Run 类型为 `AGENT`、`WORKFLOW`；生命周期状态为 `RUNNING`、`SUSPENDED`、`COMPLETED`、`FAILED`、`CANCELLED`、`TIMED_OUT`，暂停原因独立使用 `USER_INPUT` 或 `APPROVAL`。入口由执行请求归一化为 `DEBUG`、`EMBED`、`GATEWAY`、`API`、`EVAL`、`REPLAY`、`A2A` 等值；不要把 Span 的 `SUCCESS` 当成根 Run 状态。

`RuntimePublicController` 提供 `/api/traces/{traceId}` 和 `/api/traces/recent`，并提供更完整的 RunOps 接口：

- `/api/runops/traces/{traceId}`：聚合 Tool log、span、Guard 决策、版本快照和 GraphSpec。
- `/api/runops/traces/recent`：最近运行。
- `/api/runops/diagnostics`：运行诊断。
- `/api/runops/traces/{traceId}/replay`：以新 Run 按历史快照重放。
- `/api/runops/traces/{traceId}/compare/{candidateTraceId}`：运行对比。

管理端入口是 `RunOpsList.vue`、`RunOpsDetail.vue`，Studio 内也能打开 Trace 回放和节点运行摘要。

Agent 配置发布时，`runtime_agent_workflow_tool.workflow_version_id` 固定每个 Workflow-as-Tool 的发布版本。执行和回放都使用固定版本，不在运行时重新解析 Workflow 当前 ACTIVE 版本。`runtime_run.snapshot_json` 保存 Agent 配置、可调用 Workflow 的运行时投影和版本审计快照；回放 Run 以 `entry_type=REPLAY`、`replay_of_trace_id=<source>` 记录，历史配置或固定版本不可解析时必须明确失败，不能降级到当前配置。

### Tool ACL 与 Guard

`ControlToolAclController` 提供 `/api/tool-acl`：

- 角色列表、规则 CRUD、启停、批量授权。
- `/explain` 用于解释某个角色对某个 Tool/Capability 的决策。

`control_tool_acl` 支持 `role_code`、`project_id`、`project_code`、`target_kind`、`target_name`、`permission`、`enabled`。当前源码已具备 CRUD、批量授权和 `/explain` 决策解释；MCP `tools/call` 已复用同一项目级判定核心强制执行。其他 Runtime 调用路径仍须逐入口核实，不能把管理表存在泛化为“LLM 已经看不到所有未授权能力”。

`RuntimeTraceCenterController` 当前提供：

- `/api/trace-center/guard-decisions`：查询 `runtime_guard_decision_log`。

`runtime_guard_decision_log` 记录 `trace_id`、项目/环境/租户、`target_kind`、`target_name`、决策类型、原因和策略。当前不存在 `/api/trace-center/preflight/agent` 路由，发布前检查不得引用该旧契约。

### MCP

MCP 已按独立产品模块 **MCP 互联中心（MCP Hub）** 重塑，权威产品契约与实施状态见：

- [MCP 互联中心产品设计](architecture/mcp-hub-product-design.md)
- [MCP 互联中心实施计划](plans/mcp-hub-implementation-plan.md)

当前状态为 `M1_CODE_VERIFIED_DEPLOYMENT_E2E_PENDING`：出向（对外发布 + 协议执行 + 管理 + 审计）源码已按修订驱动模型落地并通过回归，但开发库升级、全新部署、浏览器业务流和真实外部客户端双源 E2E 尚未完成；入向外部 MCP 注册与编排接入（M2/M3）未实现。主线契约包括：

- 管理 API 使用 `/api/mcp/publications/**`（含挂接在发布单元下的 `/api/mcp/publications/{publicationId}/clients/**`）、`/api/mcp/overview`、`/api/mcp/call-logs`，要求平台登录会话与 `mcp-hub:*` 权限。
- 领域模型以 Publication / Publication Item / Publication Revision / MCP Client 为核心：发布产生不可变修订快照，`tools/list` 与 `tools/call` 只服务当前修订的冻结工具投影，条目引用 Capability 或已发布 Workflow（WORKFLOW 固定 ACTIVE 版本）。
- Client 凭证挂接单一 Publication，持有 API Key（明文仅创建时返回一次，库内只存 SHA-256）、tool scope 与凭证状态（ROTATED / REVOKED 不可逆）。
- 公共协议面默认关闭；启用后由 `GET /mcp/manifest`、`POST /mcp` 与兼容入口 `POST /mcp/jsonrpc` 提供 legacy `2025-11-25` / modern `2026-07-28` 双版本 Streamable HTTP，并校验 `Authorization: Bearer <MCP API key>`；`tools/list` = 修订快照 ∩ Client tool scope，IRREVERSIBLE 工具必须 Client 显式 opt-in 才可见。
- `tools/call` 先经 Tool ACL 决策（DENY 返回 POLICY 错误），再经 Runtime internal `POST /internal/runtime/mcp/tool-executions`（HMAC `MCP_REMOTE_CLIENT` 身份）执行：CAPABILITY 走 Capability 目录调用，WORKFLOW 执行修订固定的 GraphSpec 快照。
- 所有调用写入 `control_mcp_call_log`（direction / error_category 分层），管理端统一入口为 `MCP 互联`（总览、对外发布、调用流水）。
- 数据表为 Control-owned `control_mcp_publication`、`control_mcp_publication_item`、`control_mcp_publication_revision`、`control_mcp_client`、`control_mcp_call_log`；旧 `control_mcp_visibility` 与 `toolWhitelistJson` 白名单模型已退役，不得复活。

### A2A

A2A 已按独立产品模块 **A2A 互联中心（A2A Hub）** 重塑，权威产品与技术契约见：

- [A2A 互联中心产品设计](architecture/a2a-hub-product-design.md)
- [A2A 互联中心技术架构](architecture/a2a-hub-architecture.md)

当前 A2A Hub 状态为 `CORE_E2E_VERIFIED_PRODUCTION_GATES_PENDING`。核心入站、固定远端修订、Supervisor 出站委派、Task 查询/取消、Trace 关联和独立远端 E2E 已有专题证据；异步输入/授权恢复、streaming/subscribe/push、GraphSpec 远端节点、生产认证/韧性、稳定快照全量回归和 TCK 门禁仍未完成。主线契约包括：

- 管理 API 使用 `/api/a2a-hub/**`，以 Publication/Revision、Principal、Trust Profile、Credential、Task/Event/Artifact 为领域资源。
- 标准 Agent Card 使用 Host-based `GET /.well-known/agent-card.json`；协议入口使用 A2A 1.0 HTTP+JSON `/a2a/v1/**`，要求 `A2A-Version: 1.0` 和 `application/a2a+json`。
- 入站身份从 API Key 等认证结果形成稳定 Principal；请求 metadata 不得提升为用户、租户、角色或 scope。
- Message/Artifact 正文按策略加密保存，Transport Audit 只记录无正文、无凭据的安全摘要。
- Task/Event 与 durable outbox 在 Control 持久化；Runtime 只通过专用 HMAC internal API 执行固定 Agent 配置和真实取消。
- 管理端统一入口为 `A2A 互联中心`，内部包含总览、本地发布、远程 Agent、任务中心、信任与策略、开发与诊断六个工作区。

专题文档记录了开发库升级、真实远端/浏览器链路和部分 TCK 结果，同时明确这些证据不能替代稳定快照、部署健康或生产放行。以 [A2A Hub 技术架构的完成审计](./architecture/a2a-hub-architecture.md#21-完成审计) 为准。

### 市场与领域治理

`ControlMarketController` 提供 Agent 提交、审批、依赖检查和导出，数据表是 Control-owned `control_market_item`。Agent 上架快照来自 Runtime agent lookup。`DomainController` 提供领域定义、资产归属、自动分类和覆盖率，数据表是 `capability_domain_def`、`capability_domain_assignment`，前端入口是 `DomainList.vue`、`DomainAssignmentBoard.vue`、`DomainClassifierTest.vue`。

## 仍待补齐

- GuardRuntime 目前有决策日志、预检和 ACL 基础，但限流、熔断、人工审批和跨协议统一策略仍需要继续收口。
- MCP Hub 出向源码（发布、协议执行、Tool ACL、审计）已按修订驱动模型重塑；开发库升级、全新部署、浏览器业务流、真实外部客户端 E2E，以及入向外部 MCP 注册/同步与编排接入（M2/M3）仍待完成。A2A Hub 核心互操作与真实出站委派已有开发证据，但异步完整性、TCK/稳定快照和生产门禁仍需收口。
- Gateway 入口已经存在，但认证、租户身份转换、成本归集和协议层限流还需要产品化。
- RunOps 根事实、通用 Span 和版本固定模型已经统一；后续应继续补齐面向运营的故障分类、审批处置审计和修复建议。
