# 运行治理与开放协议

## 定位

运行治理负责回答“谁在什么时候、以什么身份、调用了什么能力、为什么被允许或拒绝、出了问题如何复盘”。开放协议负责把平台内的 Tool、Capability 和 Agent 安全暴露给外部 IDE、业务系统和远程 Agent。

## 当前已落地

### 执行入口

| 入口 | 用途 | 代码 |
| --- | --- | --- |
| `/api/runtime/agents/execute`、`/api/runtime/agents/execute/detailed` | Agent Supervisor 同步执行和详细执行 | `RuntimePublicController` |
| `/api/runtime/agents/execute/stream` | Agent Supervisor SSE 执行；输出规划/Workflow 步骤、回答、UI 请求和完成事件 | `RuntimePublicController`，由 Control 无缓冲转发 |
| `/api/runtime/agents/sessions/{sessionId}` | 清理 Agent Supervisor 会话记忆 | `RuntimePublicController` |
| `/api/v1/agents/{key}/chat` | 面向业务方的 Agent key 调用 | `reachai-control-service` `ControlRuntimePublicController` -> `reachai-runtime-service` |
| `/gateway/catalog`、`/gateway/agents/{key}/chat` | AI Gateway 目录和调用入口 | `reachai-control-service` `ControlRuntimePublicController` -> `reachai-runtime-service` |

Agent 执行统一进入 `RuntimeAgentExecutionService`，解析当前 ACTIVE Agent 配置版本及 Workflow-as-Tool 白名单，再交给 `SupervisorRuntimeAdapter`。旧的 Lightweight Chat `/api/chat` 主路径已删除；模型调试继续使用 Model Gateway `/model/chat/stream`，业务嵌入对话继续使用 `/api/embed/chat/sessions/{sessionId}/messages/stream`，两者不属于 Agent 调试模式。

### Trace 与 RunOps

RunOps 按“一个根事实 + 三类子事件”组织：

- `runtime_run`：每次用户或外部入口执行一行，是最近运行、KPI、趋势、诊断、对比和回放的唯一根事实。Agent 零 Workflow 直接回答也必须存在 Run。
- `runtime_trace_span`：Supervisor、PLAN、REPLAN、Workflow-as-Tool、Workflow Graph 节点和 LLM 等父子 Span。
- `runtime_tool_call_log`：底层 Tool / Capability 调用、耗时、状态、输入输出摘要和召回轨迹。
- `runtime_guard_decision_log`：Guard 的允许、拒绝和确认决策。

Tool 与 Span 都不是根运行类型，不能再通过“是否存在 Tool 日志”推断一次运行。根 Run 类型为 `AGENT`、`WORKFLOW`；状态为 `RUNNING`、`SUCCESS`、`FAILED`、`WAITING_APPROVAL`、`CANCELLED`、`TIMEOUT`；入口为 `DEBUG`、`EMBED`、`GATEWAY`、`API`、`EVAL`、`REPLAY`、`WORKFLOW_STUDIO`、`A2A`。

`RuntimePublicController` 提供 `/api/traces/{traceId}` 和 `/api/traces/recent`，并提供更完整的 RunOps 接口：

- `/api/runops/traces/{traceId}`：聚合 Tool log、span、Guard 决策、版本快照和 GraphSpec。
- `/api/runops/traces/recent`：最近运行。
- `/api/runops/diagnostics`：运行诊断。
- `/api/runops/traces/{traceId}/replay`：以新 Run 按历史快照重放。
- `/api/runops/traces/{traceId}/compare/{candidateTraceId}`：运行对比。

管理端入口是 `RunOpsList.vue`、`RunOpsDetail.vue`，Studio 内也能打开 Trace 回放和节点运行摘要。

Agent 配置发布时，`runtime_agent_workflow_tool.workflow_version_id` 固定每个 Workflow-as-Tool 的发布版本。执行和回放都使用固定版本，不在运行时重新解析 Workflow 当前 ACTIVE 版本。`runtime_run.snapshot_json` 保存 Agent 配置、工具目录和 Workflow 版本审计快照；回放 Run 以 `entry_type=REPLAY`、`replay_of_trace_id=<source>` 记录，历史配置或固定版本不可解析时必须明确失败，不能降级到当前配置。

### Tool ACL 与 Guard

`ToolAclController` 提供 `/api/tool-acl`：

- 角色列表、规则 CRUD、启停、批量授权。
- `/explain` 用于解释某个角色对某个 Tool/Capability 的决策。

`tool_acl` 支持 `role_code`、`project_id`、`project_code`、`target_kind`、`target_name`、`permission`、`enabled`。`ToolAclService` 在 Agent 装配阶段参与过滤，目标是让 LLM 看不到不该调用的能力。

`TraceCenterController` 提供：

- `/api/trace-center/guard-decisions`：查询 `guard_decision_log`。
- `/api/trace-center/preflight/agent`：Agent 发布或运行前风险检查。

`guard_decision_log` 记录 `trace_id`、项目/环境/租户、`target_kind`、`target_name`、决策类型、原因和策略。

### MCP

`McpAdminController` 提供 `/api/mcp` 管理接口：

- `/clients`：管理 MCP Client 凭证。
- `/visibility`：管理暴露白名单。
- `/call-logs`：查看调用流水。

数据表包括 `mcp_client`、`mcp_visibility`、`mcp_call_log`。管理端入口是 `McpVisibilityBoard.vue`、`McpClientList.vue`、`McpCallMonitor.vue`、`McpOnboarding.vue`。

MCP 暴露遵循多层过滤：能力必须在 `mcp_visibility` 可见，Client 白名单允许，且 Tool ACL 与运行护栏通过。

`ControlMcpEndpointController` 提供远程 MCP HTTP 入口：

- `GET /mcp/manifest`：返回 ReachAI MCP endpoint manifest。
- `POST /mcp/jsonrpc`：校验 `Authorization: Bearer <MCP API Key>`，当前支持 `tools/list` 与 `tools/call`。`tools/list` 从 `mcp_visibility` 与 Client `toolWhitelistJson` 计算可见工具；`tools/call` 校验可见性后调用 Runtime-backed `/api/runtime/tools/{qualifiedName}/execute`，所有请求写入 `mcp_call_log`。

### A2A

`ControlA2aAdminController` 提供 `/api/admin/a2a`：

- `/endpoints`：管理对外暴露的 AgentCard endpoint。
- `/call-logs`：查看调用日志。

`ControlA2aEndpointController` 提供外部 A2A HTTP 入口：

- `GET /a2a/{agentKey}/.well-known/agent.json`：从 Control-owned `a2a_endpoint.card_json` 返回 AgentCard，并补充 `/a2a/{agentKey}/jsonrpc`。
- `POST /a2a/{agentKey}/jsonrpc`：当前支持 `message/send`、`tasks/get`、`tasks/cancel`。`message/send` 通过 Runtime Agent execution 执行，结果沉淀到 Control-owned `a2a_task`；所有外部协议调用写入 `a2a_call_log`。

数据表包括 `a2a_endpoint`、`a2a_call_log`、`a2a_task`。管理端入口是 `A2aEndpointList.vue`、`A2aSessionMonitor.vue`。

### 市场与领域治理

`ControlMarketController` 提供 Agent/Capability 提交、审批、依赖检查和导出，数据表是 Control-owned `market_item`。Agent 上架快照来自 Runtime agent lookup，Skill/Capability 上架快照来自 Capability internal Tool lookup。`DomainController` 提供领域定义、资产归属、自动分类和覆盖率，数据表是 `domain_def`、`domain_assignment`，前端入口是 `DomainList.vue`、`DomainAssignmentBoard.vue`、`DomainClassifierTest.vue`。

## 仍待补齐

- GuardRuntime 目前有决策日志、预检和 ACL 基础，但限流、熔断、人工审批和跨协议统一策略仍需要继续收口。
- MCP/A2A 已有管理和审计入口，仍需更多接入诊断，尤其是解释外部 Client 为什么看不到或不能调用某个能力。
- Gateway 入口已经存在，但认证、租户身份转换、成本归集和协议层限流还需要产品化。
- RunOps 根事实、通用 Span 和版本固定模型已经统一；后续应继续补齐面向运营的故障分类、审批处置审计和修复建议。
