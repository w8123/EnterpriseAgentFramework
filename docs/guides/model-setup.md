# 接入第一个模型

为 Agent 或 Workflow 准备一个可调用的模型实例。模型目录是选型来源，模型实例才是流程和助手实际引用的配置。

## 准备

准备模型提供商给出的服务地址、API Key 和模型标识，并确认你的账号拥有目标范围的模型管理权限。自建服务也需要符合当前 Model Gateway 支持的调用协议。

不同提供商的地址格式、模型权限和计费以其服务配置为准，不把目录中出现某个模型当成账号已经有权调用。

## 接入与测试

1. 打开管理端「模型中心」，进入接入模型流程。
2. 选择提供商，填写或选择提供商账号，核对服务地址与认证方式。
3. 发现模型或填写准确的模型标识，明确模型类型，再创建实例。
4. 对创建的实例测试连接；失败时按返回原因检查地址、凭据、模型权限和网络。
5. 在 Agent 或 Workflow 中选择该实例，保存配置并完成一次目标场景测试。

API Key 只保存在服务端，查询接口只返回 `apiKeyConfigured`，不返回密钥或其前后缀。编辑时不填写 Key 表示保留原值；改变服务地址的域名、协议或端口时必须重新填写 Key。不要将真实 Key 放进页面代码、文档或 Git。

对于使用实例自身凭据的已有模型，可以在实例详情中选择「复用连接添加模型」，填写新的模型类型和标识，先测试再创建。新实例沿用原提供商、连接和项目范围；凭据在服务端独立保存，更换或撤销凭据时需要分别更新各实例。使用提供商账号的实例请通过账号接入流程添加模型。

## 选择模型类型

| 类型 | 用途 | 何时需要 |
| --- | --- | --- |
| LLM | 对话、意图理解与生成 | Agent 或模型节点 |
| Embedding | 将文本转换成检索向量 | 知识库向量索引与检索 |
| Rerank | 对候选证据重新排序 | 所选知识库检索配置需要时 |

Embedding 模型需要与知识库集合的向量配置匹配。切换模型后，检查是否需要重新解析或重新向量化；保存设置不会自动重解析文件。

## 验证结果

- 测试连接通过，实例处于可用状态。
- 目标项目或工作空间能读取并使用实例。
- Agent 或 Workflow 的实际调用成功，运行记录指向预期模型实例。

连接测试只证明该次探测结果，完整业务效果还需使用真实输入验证。模型引用、凭据与知识库的详细规则见[数据与模型](../data.md#模型)。
