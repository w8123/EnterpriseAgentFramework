# 创建知识问答

让 Agent 基于已授权的资料回答问题，并能说明答案依据。知识库保存资料和检索设置，Agent 通过已发布的知识问答 Workflow 使用它。

## 准备

- 已[接入模型](model-setup.md)：回答用 LLM，向量检索用匹配的 Embedding，按配置选择 Rerank。
- 部署环境的 Milvus 可用；PDF、Word 等文档按环境配置 Docling。
- 账号具有目标范围的知识库管理权限，明确哪些用户可以检索。

环境开关与依赖检查见[部署与运维手册](../部署与运维手册.md)，模型与检索契约见[数据与模型](../data.md)。

## 1. 创建并设置知识库

选择正确的项目、工作空间或共享管理范围，填写基本信息、模型引用、切分与检索设置。明确业务检索范围：

| 设置 | 谁可以检索 |
| --- | --- |
| ALL_CALLERS | 允许调用使用该知识库的 Agent 的用户 |
| FILE_GRANTS | 文件授权会保存；身份域隔离完成前，运行时暂不能检索这些文件 |

管理范围和业务检索范围是不同概念。能在管理端看见知识库，不等于业务员工可以读取所有文件。

## 2. 导入并核对解析

上传资料，查看导入任务、解析结果、段落与索引状态。确认正文、表格和来源定位正确，没有把解析失败或空内容当成入库完成。

保存新设置不会自动重解析已有文件；变更模型或切分规则后，按界面提供的操作处理，并检查任务结果。

## 3. 做检索测试

准备资料中有答案、没有答案、无权限和容易混淆的问题。检查命中文本是否相关、来源是否正确、目标用户是否有权访问。

检索不到时依次检查解析、向量化、模型匹配、检索范围和文件授权，再调整召回参数。运行时、旧 RAG 和查重检索中，只要任一目标知识库检索失败，本次调用返回错误，不把部分结果或失败当作完整结果。

## 4. 发布知识问答流程

在 Workflow 中配置知识检索和回答所需节点、模型及输出，明确证据策略。使用 `REQUIRED` 时，无证据应说明当前未找到可用依据，不能据此断言资料不存在；检索范围、授权和检索配置都可能影响结果。

校验并发布流程，加入 Agent 的可调用范围，再发布 Agent 配置。编排与发布顺序见[第一个 Workflow](first-workflow.md)。

## 5. 验证员工实际使用

从目标业务入口验证回答、引用来源和无证据结果，再切换真实授权不同的用户检查隔离。管理员的检索测试通过不替代员工场景验收。状态与待验条件统一见[当前边界](../status.md)。
