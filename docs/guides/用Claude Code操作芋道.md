# 员工使用自己的 AI 工具

前提是芋道已[接入 ReachAI](芋道ERP接入ReachAI实施步骤.md)，员工在芋道 AI 面板中能使用自己的业务身份。员工无需理解 MCP 或另行提交授权流程。

## 管理员开通

1. 在 **MCP 开放 → MCP 服务** 中添加需要的业务方法或已发布 Workflow，检查并发布。
2. 在服务详情 **接入与使用 → 员工使用** 中选择芋道项目，开启员工使用并设置显示名称。
3. 按业务系统角色设置调用权限。写操作默认按服务策略先审批，不向员工开放不可逆操作。

## 员工连接

1. 在芋道 AI 面板点 **在我的 AI 工具中使用**。
2. 选择系统和 Claude Code、Codex 等工具，生成连接。
3. 复制面板生成的命令或配置，按提示应用到自己的工具，再发起业务请求。
4. 在“我的连接”管理和断开；需要独立页面时，从面板点 **在浏览器里管理**。

使用平台实际生成的地址、配置与有效期，不手工拼接协议或复制他人的密钥。连接内容只显示一次；不要转发，丢失后断开并重新生成。员工停用、连接断开或过期后不能继续调用。

## 写审批与查询

员工请求新建客户等非只读操作后，工具返回审批单，不立即执行。管理人员、运营人员或平台管理员在 **MCP 开放 → 写操作审批** 检查并选择通过执行或驳回。

通过时重新检查连接、身份、权限与能力契约，参数不可修改；同一审批不得重复派发。员工可用 `reachai_approval_status` 或“我的审批”查看结果。过期、驳回与执行失败分别显示。

## 复用经验

运营人员可从 **调用记录** 或运行详情选择成功记录，生成 Skill 草稿，确认只包含工具、字段与顺序，保存后审核发布。员工在面板的 **可用的做法** 中下载当前项目允许的包，按工具支持的方式安装。

需要固定流程时生成 Workflow 草稿，在 Studio 中确认和编排后发布；生成草稿不等于已经发布或可运行。治理与身份规则见[开放协议](../protocols.md)。

## 查看结果

管理员从员工连接、调用记录和运行中心核对“谁、用什么工具、对哪个系统做了什么”。真实数据、业务权限与最终操作人以芋道为准；查不到或执行失败时保留错误原因，不通过换账号或重发写操作绕过。
