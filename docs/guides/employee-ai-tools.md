# 员工 AI 工具接入

让员工在自己的 Codex、Claude Code 等兼容客户端中，以本人业务身份使用企业已经开放的能力。员工无需成为 ReachAI 管理员。

## 先区分连接类型

| 目标 | 使用的连接 | 创建入口 |
| --- | --- | --- |
| 查询和办理业务系统中的业务 | 员工个人连接 | 业务系统 AI 面板 |
| 管理获授权的 ReachAI 平台资源 | 平台 AI 连接 | 管理端个人中心 |
| 接入特定项目的开发与编排 | 项目 AI Coding Key | 项目接入工作台 |

三种凭证的身份和权限不同。这里介绍员工个人连接；另外两种见[开放协议](../protocols.md#平台-ai-连接)与 [AI Coding](../ai-coding.md)。

## 管理员准备

1. 业务系统已接入可信业务身份，员工能在嵌入面板正常使用。
2. 在「MCP 开放 → MCP 服务」加入允许使用的业务方法或已发布 Workflow，检查并发布。
3. 在服务的「接入与使用 → 员工使用」中开通对应系统，设置写审批策略。
4. 按业务角色核对调用权限，并确认员工电脑能访问生成的服务地址。

HTTP API 通过已发布的 Workflow 暴露。服务发布、允许调用与业务数据权限分别验证。

## 员工连接

1. 登录原业务系统，在 AI 面板点击「在我的 AI 工具中使用」。
2. 选择系统和客户端，生成个人连接。
3. 复制平台为该客户端生成的命令或配置，按提示应用。
4. 先发起一个只读请求，再到「任务记录」核对调用结果。

使用实际生成的地址、认证配置和有效期，不手工猜测路径。密钥仅在生成时显示，不转发给别人；丢失后断开原连接并重新创建。客户端能否连接还取决于其远程 MCP 与认证支持，见[当前边界](../status.md)。

## 写操作与审批

服务策略要求审批时，非只读调用先生成审批单，冻结身份、能力版本与参数。审批人从「MCP 开放 → 写操作审批」核对后通过执行或驳回。

员工在「我的审批」查看状态，也可以使用 `reachai_approval_status` 查询原审批。结果未知时先查询，不换请求编号反复发送。审批不会授予业务系统中原本没有的权限。

## 管理与断开

在业务系统面板点击「在浏览器里管理」，进入员工个人页，查看可用能力、连接、任务、审批和记忆。断开不再使用的连接；员工停用、连接过期或权限撤销后，后续调用会被拒绝。

需要复用已验证的做法时，下载当前系统允许的已发布 Skill，按客户端支持方式安装。具体业务实例见[用 Claude Code 操作芋道](用Claude%20Code操作芋道.md)。
