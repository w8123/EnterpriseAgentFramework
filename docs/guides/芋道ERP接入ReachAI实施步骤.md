# 芋道 ERP 接入

通用机制先读[系统接入](../integration.md)。这里只保留芋道自身的适配点；快速体验直接使用 [Docker 演示](../../deploy/quickstart/README.md)。

## 应用补丁

- [后端与业务方法补丁](yudao/yudao-reachai-integration.patch)：SDK、身份桥、嵌入令牌解析和 ERP 能力声明。
- [页面补丁](yudao/yudao-ui-reachai-chat.patch)：在芋道布局中接入对话与页面通道。

先在芋道根 POM 和 `yudao-server/pom.xml` 中启用 ERP 模块，再在目标 checkout 执行 `git apply --check <补丁路径>`，核对当前上游代码与冲突后再应用。依赖版本使用本平台 onboarding manifest 给出的制品，不按示例推断兼容所有芋道版本。

## 后端配置

项目使用独立 code 和凭据，扫描范围限定 ERP 包。仅业务方法使用 `ANNOTATED_ONLY`；需要同时发现 Controller API 时选择 Starter 支持的对应模式。

`/reachai/**` 交给 Starter 校验签名和调用令牌，芋道侧放行该受保护入口，不能取消 Starter 鉴权。业务执行通过 `YudaoReachAiSecurityBridge` 还原 `LoginUser`、租户和角色，再沿用芋道的数据权限与事务。

员工调用必须对应本人账号；身份桥要求调用令牌包含有效的芋道租户编号和用户编号，缺失或无效时拒绝调用。配置中的平台地址和凭据文件使用目标环境真实配置，敏感内容不提交。

芋道的全局异常处理可能以 HTTP 200 返回 `CommonResult` 业务码 403；调用结果应同时检查业务码，不能只凭 HTTP 状态判定成功。ReachAI 会将该业务响应识别为失败。

## 嵌入与员工工具

业务后端通过 `YudaoReachAiEmbedPrincipalResolver` 从当前登录态解析身份。平台配置允许来源、项目与 Agent，前端加载构建的 Embed SDK，由后端换取短期令牌。浏览器不保存项目 appSecret。

示例可将 Embed Token 绑定到芋道登录会话：后端校验当前访问令牌的用户、类型与租户，再对刷新令牌派生不可逆的会话标识；刷新令牌不能直接用于换取 Embed Token。刷新访问令牌不会更换会话标识，Embed Token 有效期不会超过验证过的业务访问令牌。换发使用芋道共享的登录刷新队列。退出和批量下线的撤销通知采用宿主数据库队列，失败后重试，通知送达前令牌仍可使用。该能力默认关闭：先升级 ReachAI Control、Capability 与 Starter，备份并在芋道目标库应用补丁中的 `sql/mysql/reachai-logout-outbox.sql`，核对表结构，再设置 `reachai.logout-revocation.enabled=true` 并重启芋道。队列不可写时，令牌删除会失败；ReachAI 网络不可用时退出仍可完成，通知留在队列等待重试。不能将这一流程视为即时撤销或中止已在途请求；完整目标环境验收仍需覆盖退出、强制下线、断网恢复与令牌续签竞态。

前端通过 `VITE_REACHAI_BASE_URL` 指定 ReachAI 地址、`VITE_REACHAI_AGENT_ID` 指定 Agent 标识；不配置时不显示入口。令牌接口默认使用 `VITE_BASE_URL` 下的 `/reachai/embed/token`。如果本地测试使用独立的芋道后端，可通过 `VITE_REACHAI_TOKEN_URL` 指定该后端的完整令牌接口地址；此接口会收到芋道登录令牌，必须指向可信的芋道后端。修改 Vite 环境变量后需要重启开发服务器或重新构建。

页面补丁为 ERP 产品列表登记按名称筛选动作：它清除分类条件、返回第一页并调用芋道已有查询接口，不修改业务数据。用户主动切换路由时销毁旧对话并创建新实例；该示例不保留跨页面对话，也不提供平台发起的跨页面导航。示例暂时隐藏个人记忆入口，隐藏按钮不等于服务端隔离或撤销权限，生产接入前仍需处理 [已知隔离问题](../status.md)。

产品列表会丢弃已被新查询、条件修改或离开页面淘汰的响应；AI 筛选遇到这些情况会报告未完成。应用页面补丁后，可在芋道前端目录运行 `node scripts/test-reachai-product-query.cjs` 检查并发行为，再使用真实业务账号和页面验证。

Agent 的介绍和系统提示词应与实际发布并绑定的 Workflow 一致。已扫描到业务方法不代表助手已经能调用：例如销售统计方法存在，但若没有对应 Workflow 和 Agent 绑定，应说明当前助手尚未接入，不要断言芋道系统没有该功能。调整绑定后重新验证可用能力及写操作确认。

需要员工在自己的 AI 工具中使用时，按[员工指南](用Claude%20Code操作芋道.md)开通 MCP 服务、调用权限与写审批。

## 工作流调试限制

Studio 的整稿只读试运行使用项目测试身份，不代表已登录的芋道员工；当前身份桥会拒绝缺少真实员工和租户的调用。即使业务方法被声明为只读，也不能用该入口验证芋道员工权限或业务查询结果，应在已发布 Agent 的嵌入对话中使用实际员工登录态验收。芋道能力通过 `businessIdentityRequired = true` 显式声明该要求，平台预检可据此拒绝项目身份试调用；业务后端仍须验证真实用户、租户和权限。升级已有接入时，先升级 SDK 和平台，再同步并评审能力契约变化。

当前整稿试运行表单和服务端仅接受标量输入；如商品查询工作流输入使用 `pageReqVO` 对象，该入口不能填写这一参数。这是试运行入口的限制，不代表正式工作流不能接收对象，也不要为了通过预检而移除芋道身份校验。

## 验收

1. 注册实例、心跳、同步与变化评审对应同一项目和真实来源。
2. 核对产品、仓库、客户等返回 DTO 的业务包装和字段路径，再试调用。
3. 员工查询结果与芋道一致，写操作先审批，实际创建人与当前员工一致。
4. 非白名单来源、无签名、无令牌和越权角色被拒绝；切换用户不能读取前一用户的会话或记忆。
5. 从员工连接、审批、调用记录回到同一运行与 Trace；失败能定位权限、来源、参数或契约问题。

参数与具体能力清单以补丁、平台接纳结果及芋道当前代码为准，本页不重复维护另一份接口目录。
