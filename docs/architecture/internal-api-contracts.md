# Internal API Contracts

This document is the source of truth for service-to-service internal HTTP contracts in the first physical split phase.

Internal APIs are not public frontend APIs. The frontend enters through `reachai-control-service` public `/api/**`, `/embed/**`, `/ai/**`, or `/model/**` routes only.

| `POST /internal/runtime/agents/execute` | `reachai-runtime-service` | `reachai-control-service` | Control executes Agents with HMAC-SHA256 authenticated identity + body integrity (`X-ReachAI-Internal-*`: caller, timestamp, nonce, identity source/tenantId/userId, body SHA-256, signature). V2 canonical string (ai-common `InternalServiceHmac`): `METHOD\nPATH\nCALLER\nIDENTITY_SOURCE\nIDENTITY_TENANT_ID\nIDENTITY_USER_ID\nTIMESTAMP\nNONCE\nBODY_SHA256`; rolling-upgrade V1 requests omit tenant and are pinned to `default`. Control signs the exact serialized HTTP body bytes; Runtime verifies the same raw bytes via a size-capped cached-body wrapper. Also verifies caller allowlist, clock skew, constant-time signature, and JDBC nonce anti-replay (`runtime_internal_auth_nonce`; only expired nonces may be deleted; at capacity fail-closed). Shared secret: `REACHAI_INTERNAL_SERVICE_SECRET` (Control/Runtime must match; blank → fail-closed; readiness reports `INTERNAL_AUTH_NOT_CONFIGURED`). Path name alone is never attestation. Public `/api/runtime/agents/execute` must not accept client trust flags; body tenant/user fields are never trusted for session state, Knowledge ACL, credentials, or RunOps audit identity. Control may add a bounded `personalMemory` object beside `body` in this signed envelope. Runtime strips all public body aliases, accepts only this attested object, quotes it as untrusted user context, and never copies it into Workflow input, continuation payload, or Trace. | No |
| `POST /internal/runtime/agents/execute/stream` | `reachai-runtime-service` | `reachai-control-service` | Same HMAC + body-digest auth as sync execute. SSE path must call `RuntimeAgentExecutionService.execute(..., WorkflowExecutionIdentity)`. Control Agent stream (Bearer) and Embed stream (claims userId) use this entry; public Runtime stream stays untrusted. Signatures/identity/body digests must never be written into logs, Trace, or downstream SSE. | No |
| `DELETE /internal/runtime/agents/sessions/{sessionId}` | `reachai-runtime-service` | `reachai-control-service` | User clear claims `CLEARING`, erases AgentScope short-term state and Tool-artifact ciphertext, then marks the session `CLEARED` for later retention. Control signs the exact encoded path and empty request body; Runtime verifies both before resolving ownership. Legal Hold or a live turn blocks the claim. The public Runtime delete route is fail-closed, and the durable conversation event ledger remains until the owning retention policy purges it. | No |
| `GET /internal/runtime/session-retention/tenants/{tenantId}/policy` | `reachai-runtime-service` | `reachai-control-service` | Reads the tenant's effective Runtime-owned active/cleared session retention policy, including whether it is a tenant override or the configured default. | No |
| `PUT /internal/runtime/session-retention/tenants/{tenantId}/policy` | `reachai-runtime-service` | `reachai-control-service` | Creates or updates the bounded tenant policy and writes metadata-only Runtime audit. Requires a V2 HMAC `PLATFORM_SESSION` identity with nonblank platform actor and signed tenant exactly equal to the target tenant. | No |
| `DELETE /internal/runtime/session-retention/tenants/{tenantId}/policy` | `reachai-runtime-service` | `reachai-control-service` | Deletes the tenant override, restoring configured defaults, and writes metadata-only Runtime audit under the verified platform actor. | No |
| `GET /internal/runtime/session-retention/tenants/{tenantId}/sessions/{sessionId}` | `reachai-runtime-service` | `reachai-control-service` | Reads one Runtime-owned session's lifecycle, Legal Hold, event-count, and effective policy metadata. It does not return conversation bodies, AgentScope state, Tool-result plaintext, or raw user identity. | No |
| `PUT /internal/runtime/session-retention/tenants/{tenantId}/sessions/{sessionId}/legal-hold` | `reachai-runtime-service` | `reachai-control-service` | Sets or releases Legal Hold with a machine reason code and optional bounded external reference. Hold blocks user clear, scheduled retention, and manual erase; lifecycle claims prevent hold/purge races. | No |
| `POST /internal/runtime/session-retention/tenants/{tenantId}/sessions/{sessionId}/erase` | `reachai-runtime-service` | `reachai-control-service` | Claims `PURGING`, erases Runtime AgentState, physically deletes session Tool-artifact rows, conversation events, and the session row, then retains only metadata audit with a session hash. Legal Hold and live turns fail closed. This is Runtime-session erasure, not cross-domain personal-memory, RunOps/Trace, business-system, or backup erasure. | No |
| `POST /internal/runtime/session-retention/tenants/{tenantId}/owner-erasure` | `reachai-runtime-service` | `reachai-control-service` | Physically erases one bounded batch of all sessions owned by the signed tenant plus the raw Runtime user carried only in the exact-byte HMAC body. The response contains only a Runtime-side owner hash and aggregate counts. Legal Hold, active turns and lifecycle leases remain authoritative; Control must repeat until `remaining=0` and must not treat a blocked batch as complete. | No |

## Guard

Run the contract guard after adding or changing an internal endpoint:

```powershell
node scripts/check-internal-api-contracts.mjs
```

The guard discovers Spring mapping annotations under the five service source roots, requires every `/internal/runtime/**`, `/internal/capability/**`, and `/internal/control/**` contract to be listed above, and fails if `ai-admin-front` calls an internal service API directly.
