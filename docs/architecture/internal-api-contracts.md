# Internal API Contracts

This document is the source of truth for service-to-service internal HTTP contracts in the first physical split phase.

Internal APIs are not public frontend APIs. The frontend enters through `reachai-control-service` public `/api/**`, `/embed/**`, `/ai/**`, or `/model/**` routes only.

For `ControlRuntimePublicController`, `RuntimeProxyExceptionHandler` takes precedence over generic exception advice: Runtime 404 and 409 responses retain their HTTP status, response body and non-transport headers; connection failures retain the existing 504 mapping. An absent Agent must return HTTP 404 through Control, including after deletion, rather than an HTTP 200 internal-error envelope containing a Feign request address. Tests load both advice classes to verify this precedence.

## Runtime to Capability identity

Runtime signs three distinct identity modes for both Capability invocation routes:

| Signed source | Accepted identity |
| --- | --- |
| `RUNTIME_TRUSTED_IDENTITY` | An attested business user; the signed user header matches `context.externalUserId`, and the tenant header matches `context.tenantId`. |
| `RUNTIME_TRUSTED_TENANT` | An attested tenant from a typed Runtime identity that can resolve its project credential. The tenant header and `context.tenantId` must be nonempty and equal; the user header is empty. End-user identity, role and attribute fields are forbidden. |
| `RUNTIME_UNTRUSTED` | No tenant or user headers and no identity fields in context. Public maps cannot create a trusted Runtime identity. |

Tenant-only scope preserves the verified tenant for MCP, A2A, Automation and project-scoped Agent calls without turning their service principals into business users. Capability includes that tenant in the signed SDK invocation token; the business host still owns its authorization. MCP Client roles govern the platform Tool ACL and are not business-user roles. Tenant-only calls cannot satisfy business-memory `requireUserIdentity` constraints.

For the explicit saved-draft business-method trial, Runtime requires a validated request-local pin before mapping `STUDIO_PROJECT_TEST` to `RUNTIME_TRUSTED_TENANT`. The projectCode is taken from that pin, not from input/context maps; the signed context contains only tenantId and never the platform actor as a business user. Capability rechecks project, READ_ONLY, source/accepted/current hash and active project signing credentials before the SDK endpoint. The Studio restriction flag is scrubbed from caller input and cannot independently grant authority. Ordinary debug remains untrusted and cannot dispatch BUSINESS_METHOD; trusted Eval still retains its side-effect guard.

All modes keep the exact-body HMAC, timestamp and replay checks. Upgrade Capability before Runtime when deploying the tenant-only mode; an older verifier rejects the new source rather than accepting weaker identity semantics.

For MCP capability execution, Runtime places its persisted MCP root trace ID in `context.supervisorTraceId`, the existing signed SDK correlation field. Capability copies it into the signed invocation token's `traceId`. Tool arguments, nested client context and request metadata cannot select this value. The SDK business host, MCP response, RunOps and call audit therefore share the server-generated correlation ID. This is separate from W3C traceparent or collector deployment.

## Guard

Run the contract guard after adding or changing an internal endpoint:

```powershell
node scripts/check-internal-api-contracts.mjs
```

The guard discovers Spring mapping annotations under the five service source roots, requires every `/internal/runtime/**`, `/internal/capability/**`, and `/internal/control/**` contract to be listed above, and fails if `ai-admin-front` calls an internal service API directly.
