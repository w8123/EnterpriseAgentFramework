# 常见问题与排查

从问题发生的阶段定位，先保留错误信息和原调用编号，再按同一身份、目标与输入核对。安装和服务故障先运行 `reachai doctor`；不要把重发写操作当作检查手段。

## 应该选哪一种接入方式

Java / Spring 业务系统使用 Starter 与 Capability SDK；不能改代码或非 Java 系统使用 OpenAPI 文档接入；已有页面需要对话时增加 Embed Chat；员工自己的工具使用个人 MCP 连接。详见[系统接入](integration.md)与[员工 AI 工具](guides/employee-ai-tools.md)。

## 员工必须注册 ReachAI 账号吗

不需要。员工从业务系统的可信登录态获得对话和个人连接身份。管理端账号用于接入、配置、发布、运营与平台管理，不能拿它替代业务用户。见[产品](product.md)与[身份与安全](security.md)。

## 模型连接测试失败

核对提供商地址、准确模型标识、API Key、账号模型权限及部署网络。目录中能看见模型不说明当前账号可调用。先修复实例测试，再验证 Agent 或流程，见[模型接入](guides/model-setup.md)。

## 业务实例已注册，为什么找不到或调用不了操作

分别核对扫描范围、来源同步、契约接纳、实例地址、调用身份、项目权限与 ACL。注册、发现、接纳和允许执行是独立步骤。HTTP API 还需要有效连接，见[系统接入](integration.md)与[试调用与连接](workflow.md#试调用与连接)。

## Agent 没有使用我刚修改的 Workflow

草稿保存不会改变线上版本。发布 Workflow 后，显式更新 Agent 的流程绑定并发布 Agent 配置。原版本 pin 不会自动迁移；来源契约变化也可能使旧版本拒绝执行。见 [Workflow 发布](workflow.md#graphspec-与发布)。

## 提示草稿冲突或修订失效

保留未保存内容，重新读取当前修订，比较并明确合并后再保存。不要让脚本自动获取最新修订并覆盖它。Agent、Workflow 与知识库设置各有对应的修订入口，见[开放协议](protocols.md)及[数据与模型](data.md)。

## 调用超时，或者显示 UNKNOWN

使用原 invocationId、运行编号或审批编号查询结果，并检查运行中心与业务系统。超时不证明业务没有执行，尤其不能自动重发非幂等写操作。恢复规则见 [Workflow](workflow.md#执行交互和恢复)。

## 为什么写操作一直在等待

区分运行中的人工确认与员工 MCP 写审批。到对应审批或交互界面查看状态、有效期与目标参数；批准后还会重新核对身份、权限和契约，过期或漂移可能导致执行失败。见[员工身份和写审批](protocols.md#员工身份和写审批)。

## 员工的 AI 工具连不上

先确认生成地址在员工电脑可达，公网地址没有错误地使用 localhost，HTTPS 与客户端认证方式匹配，连接未过期且服务未暂停。重新使用面板生成的配置，不复制别人的连接。见[部署手册常见问题](部署与运维手册.md#9-常见问题)。

## 知识库导入完成却没有答案

依次检查解析正文、段落、向量化状态、Embedding 配置、Milvus、检索范围与当前用户文件授权。无证据时遵守证据策略，不让模型猜测。见[创建知识问答](guides/knowledge-qa.md)。

## 我在官网看见功能，是否代表目标环境可用

文档说明当前产品与代码契约。实际可用性还取决于服务版本、数据库升级、配置、权限和目标场景验收。统一查看[当前边界](status.md)，按[运维验收](operations.md)核对。
