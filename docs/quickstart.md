# 快速入门

先跑通一个只读任务：接入模型和业务系统，发布一个查询流程，再让员工通过业务页面或自己的 AI 工具使用它。

## 选择开始方式

| 你的目标 | 使用方式 |
| --- | --- |
| 先看已接入的完整业务场景 | 按 [Docker 体验](../deploy/quickstart/README.md)启动 ReachAI 与芋道 ERP |
| 给自己或团队安装服务 | 按[部署与运维手册](部署与运维手册.md)安装，支持服务器与本机模式 |
| 修改 ReachAI 源码 | 按[开发](development.md)准备环境并启动服务 |

安装命令、硬件条件和初始账号均以对应手册为准。团队部署使用安装时生成的初始密码，Docker 演示账号仅用于本机体验。

## 第一步：登录并接入模型

打开安装完成后给出的管理端地址。平台管理员可以从「开始使用」进入引导，检查系统体检结果。

在「模型中心」接入提供商账号，创建需要的模型实例并测试连接。普通对话使用 LLM；知识库另需 Embedding，按检索策略选择 Rerank。操作见[接入第一个模型](guides/model-setup.md)。

**完成标志**：模型实例的连接测试通过，目标项目有权使用它。

## 第二步：接入业务系统

- Java / Spring 系统：引入 Starter 与 Capability SDK，注册业务实例，声明允许 AI 调用的方法。
- 其他系统：在项目接入时上传 OpenAPI / Swagger 文档，再配置实际调用连接。

先选择一个没有写入副作用、输入输出清楚的查询，例如查询当前用户可见的订单。同步后核对来源、契约、身份和调用权限，执行一次受控试调用。完整步骤见[系统接入](integration.md)。

**完成标志**：目标方法或 API 已接纳，试调用返回预期业务数据，业务权限确实生效。

## 第三步：创建流程与助手

按[创建第一个 Workflow](guides/first-workflow.md)编排查询流程，检查输入、输出映射，保存、校验并发布。创建 Agent，选择可用模型，将已发布 Workflow 加入其可调用范围，再发布 Agent 配置。

**完成标志**：已发布的 Agent 能调用指定版本的流程；从运行记录能定位到同一次调用。

## 第四步：选择员工使用入口

| 使用场景 | 下一步 |
| --- | --- |
| 员工留在原业务系统办理业务 | [在业务页面嵌入对话](guides/embed-chat.md) |
| 员工使用 Codex、Claude Code 等工具 | [员工 AI 工具接入](guides/employee-ai-tools.md) |
| 希望使用内部资料回答问题 | [创建知识问答](guides/knowledge-qa.md) |
| 希望编码工具操作 ReachAI 管理资源 | [AI Coding](ai-coding.md)与[平台 AI 连接](protocols.md#平台-ai-连接) |

## 上线前检查

确认真实业务身份、项目隔离和调用权限；增加写操作时，再验证确认与审批、超时后的结果查询和重复请求保护。安装成功、来源同步成功、流程发布成功和真实业务验收分别检查。

上线条件见[运维与验收](operations.md)，支持范围与待验内容见[当前边界](status.md)。遇到问题先看[常见问题](faq.md)。
