# 项目注册与能力资产

## 定位

项目注册与能力资产是睿池 ReachAI 的入口层。历史系统可以通过平台扫描接入，可改造系统优先通过 `reachai-spring-boot2-starter` 与 `reachai-capability-sdk` 主动注册。两条路径最终都形成项目、实例、接口资产与能力目录；SDK 的可信上报由系统按策略接纳，无法自动确定的变化才进入待处理视图；运行时再把已纳管能力投影成模型可调用协议。

## 当前已落地

### 接入路径

| 路径 | 适用对象 | 当前实现 |
| --- | --- | --- |
| 平台扫描 | 历史系统、PoC、无法改造项目 | `CapabilityScanProjectCatalogController`、Knowledge `ScannerController`、`capability_scan_project`、`capability_scan_project_tool` |
| SDK 主动注册 | 新系统、可改造业务系统 | `ReachAiRegistryClient.registerAndSync()`（历史方法名，当前执行项目注册和实例心跳）、`CapabilityRegistryCompatibilityController`、`capability_project_instance` |
| SDK 图同步 | 由业务代码声明或生成的运行图快照 | `/api/registry/projects/{projectCode}/agent-graphs/sync` 经 Control 委托 Runtime 兼容入口 |
| 能力目录治理 | 已经自动或人工接纳、可供 Workflow 引用的业务能力 | `GET /api/tools` 只读投影、`/api/capability-review/**` 项目级评审；旧 `/api/capabilities/**` 模块/Tool/Composition/Interaction 人工编辑入口已退役 |

### SDK 契约

`reachai-capability-sdk` 提供业务能力声明和接入契约：

- `@ReachCapability`：声明业务方法或 Controller 方法可作为 Agent 能力。
- `@ReachParam`：补充参数语义、示例、来源和约束。
- `@ReachOutput`：声明返回 DTO 字段是否可被后续节点引用，不用于方法级标注。
- `ReachAiSigner`：生成 `X-ReachAI-*` 签名头。

`ai-runtime-contract` 承载以下中台内部运行时契约：

- `reachai-business-memory-reference-v1`：Knowledge 检索投影指向业务事实源的非权威、带版本引用。
- `reachai-business-memory-resolution-v1`：业务 resolver 在当前签名身份下重新鉴权后返回的时点事实。

业务记忆 resolver 仍通过普通 `@ReachCapability` 注册，但必须接受 `resourceType`、`resourceId`、`expectedSourceVersion`，校验 `X-ReachAI-Invocation-Token` 的当前 tenant/user，并返回 resolution 契约。JDK 8 业务系统复用 `ReachBusinessMemoryResolverRequest`、`ReachBusinessMemoryAccessScope.authorizeRow(...)` 与 `ReachBusinessMemoryResolution.createAuthorized(...)`；带 `business-memory-resolver` 标签时，Starter 会在业务调用前后强制校验签名 scope、行授权证明和返回资源一致性。索引中的 `search_text` / metadata 只用于发现，不能作为 resolver 的授权输入或当前业务事实。完整示例和失败语义见 [Personal Agent Memory](./architecture/personal-agent-memory.md#业务记忆引用契约) 和 `reachai-spring-boot2-starter/README.md`。

`reachai-spring-boot2-starter` 提供接入自动化：

- `ReachAiRegistryProperties` 使用 `reachai.registry`、`reachai.project`、`reachai.capability` 配置。
- `ReachCapabilityBeanScanner` 基于 `@ReachCapability`、`@ReachParam` 和请求体反射生成能力描述。
- `ReachAiRegistryClient` 启动时完成项目注册和实例心跳；能力扫描/同步由 API 管理手动触发，SDK 图同步保留独立契约。
- `ReachCapabilityEndpoint` 暴露 `/reachai/capabilities/{name}/invoke`，作为业务系统 Capability Host 的本地调用入口。
- `ReachCapabilitySyncEndpoint` 暴露业务系统侧 `POST /reachai/registry/capabilities/sync`。ReachAI 服务端通过在线实例地址调用该入口，Starter 验证注册签名后现场扫描，并把快照回传注册中心。

### API 管理手动 SDK 同步

手动同步是两跳服务端链路：

1. ReachAI 根据在线实例的 `baseUrl` 和项目 `contextPath`，调用业务系统 `POST /reachai/registry/capabilities/sync`。
2. 业务系统 Starter 扫描配置范围，并调用 ReachAI `POST /api/registry/projects/{projectCode}/capabilities/sync` 回传能力快照。
3. SDK 回传固定使用 `apply=false`，Capability 服务也会忽略旧客户端在 sync 请求中携带的 `apply=true`；平台按项目串行校验、去重与记录来源。完整的新增只读能力、纯展示名称更新可自动接纳；契约、语义与副作用等不确定变化保留待处理。人工 `APPLY` / `IGNORE` 仍受平台会话、项目级 RBAC 与 Control→Capability 精确请求体 HMAC 保护。忽略只收起本次变化；回滚只恢复目录，不恢复业务代码。调用前会检查最新可信来源与目录、发布契约是否一致。具体规则见 [能力变化自动治理](architecture/capability-change-governance.md)。

业务系统需要保证第一跳从 ReachAI 所在网络可达。如果 `baseUrl` 指向网关，网关必须将 `/reachai/registry/**` 转发到 Starter 所在服务，并透传 `X-ReachAI-App-Key`、`X-ReachAI-Timestamp`、`X-ReachAI-Nonce`、`X-ReachAI-Signature`。Spring Security、Sa-Token、Shiro、自研登录拦截器和 CSRF 应允许该签名请求到达 Starter Controller，但不能关闭 Starter 自身的签名校验；无签名或签名错误仍返回 `401`。这是服务端调用，不涉及 CORS。

`reachai.project.base-url` 表示 ReachAI 服务端眼中的业务系统地址。`localhost`、`127.0.0.1` 或 `::1` 只适用于 ReachAI 与业务系统同机或共享网络命名空间的联调环境。

### 注册中心接口

当前 Registry 公共路径由 Control 收口，并委托 Capability/Runtime owning implementation。关键接口包括：

- `POST /api/registry/projects/register`：注册项目和接入凭证。
- `POST /api/registry/projects/{projectCode}/instances/heartbeat`：业务实例心跳。
- `POST /api/registry/projects/{projectCode}/instances/offline`：实例下线。
- `POST /api/registry/projects/{projectCode}/capabilities/sync`：SDK 同步能力快照；服务端按自动接纳策略处理可信来源，旧 `apply` 字段不具有审批权。
- `POST /api/registry/projects/{projectCode}/agent-graphs/sync`：同步 SDK 图。
- `/api/capability-review/**`：管理端专用的快照、差异、逐项评审、回滚和开发诊断入口；由 Control 校验平台会话与 `PROJECT` scope，读取要求 `platform:read`，写入要求 `platform:write`，审计 operator 强制取当前登录用户。
- `POST /api/capability-review/projects/{projectCode}/capabilities/diff|sync`：开发诊断请求；两者都只生成 `DIAGNOSTIC` 记录，不改变目录、真实来源或用户待办。
- `GET /api/capability-review/projects/{projectCode}/changes`：按能力查询当前待处理或处理记录；支持 `state=PENDING|PROCESSED|ALL`、`keyword`、`current`、`size`，单页最多 50 项。Control 汇总 Runtime 与 MCP/A2A 的真实引用证据，失败或不完整明确标为未知。
- `GET /api/capability-review/projects/{projectCode}/snapshots`、`GET /api/capability-review/projects/{projectCode}/snapshots/{snapshotId}/diff-items`、`POST /api/capability-review/projects/{projectCode}/diff-items/{diffItemId}/review|rollback`：正式管理端评审链路；路径与 Capability owner 会双重校验资源归属，防止用 ID 跨项目访问。

管理端对应 `RegistryProjectList.vue`、`RegistryProjectDetail.vue`、`CapabilitySyncDebug.vue`。

### 能力资产模型

`capability_tool_definition` 是当前能力调用的运行时投影表，不是独立业务资产：

- 只保留 `kind='TOOL'` 的可调用协议行。ReachAI 不再创建 `kind=SKILL` 目录行或 `skill_kind` 字段。
- `capability_metadata_json` 保存 `@ReachCapability`、`@ReachParam` 等声明元数据。
- `project_id`、`project_code`、`visibility`、`qualified_name` 用于项目隔离和稳定引用。
- `side_effect` 描述副作用等级，供 Studio 发布、Tool ACL 和运行护栏使用。
- 管理端不提供通用 Tool 的新建、编辑、全局启停、删除或真实执行页面；`GET /api/tools` 与 `GET /api/tools/{name}` 只保留为能力发现与运行时投影读取。真实执行统一进入带身份、ACL 与运行上下文的 Runtime 路由，来源变更进入项目扫描或 SDK 快照评审。

扫描阶段的 `capability_scan_project_tool` 是项目内来源发现与语义证据，不是第二份执行契约。SDK 可信同步与来源接纳自动维护业务方法的技术投影；Controller/OpenAPI 发现进入 HTTP API owner，在所属项目 API 目录接纳契约、配置连接并使用受控 Console。项目来源页直接导航到业务方法/API 目录，Workflow 只通过 typed picker 显式选择资产。`removed_from_source` 和 `removed_at` 保留来源移除事实，历史引用不自动迁移。

旧扫描 edit/toggle/test/promote/push/unpromote/module promote 维护路由已删除，不保留历史兼容入口。来源观察读取和重扫仍由 Capability 提供，公开 Control 先校验平台会话与项目权限。`tools/reconcile` 只读核对历史关联，不修复或写入投影。无可信来源绑定的旧 scanner 人工投影标为 `LEGACY_SCAN_TOOL_RETIRED`，在校验/派发前拒绝；旧 DRAFT、发布引用和交互 API binding 原样保留，由用户选择新 API、保存并显式发布新版本。不能按名称或 HTTP verb 猜分类，也不能把合法 SDK 自动投影一并禁用。

管理端以“业务方法”和“API”分别提供独立资产页面；旧能力目录、`/tool` 及其重定向已删除。代码在现有 Capability 服务内复用职责明确的接入、同步和调用机制；方法事实由业务方法 owner 提供，API 保持自己的来源和接纳契约。当前源码已切换，数据库、浏览器及整体验收状态见实施进度；目标边界和实施位置见[实施基线](./plans/业务方法与API重构实施基线.md)与[实施进度](./plans/业务方法与API重构实施进度.md)。

删除项目前必须按 `operation=DELETE` 查询 `GET /api/scan-projects/{id}/operation-blockers`；实际删除在项目锁内再次直接核对方法/API owner 及引用。存在资产（包括停用、来源移除或候选状态）时返回含具体资产的409，不级联删除来源、接纳修订或已发布引用。空项目仍可删除。重扫使用 `operation=RESCAN`，资产存在本身不阻止来源同步，已有引用保护继续生效。

### 语义和图谱补强

扫描接入不是终点。当前系统已经把语义文档和接口图谱接入项目资产：

- `CapabilitySemanticCatalogController` 维护项目、模块、接口级 `capability_semantic_doc`，用于让 Agent 看懂接口含义。
- `CapabilityApiGraphSnapshotController` 维护 `capability_api_graph_node`、`capability_api_graph_edge`、`capability_api_graph_layout`，支持候选边确认、参数来源提示和画布布局。
- `CapabilityScanProjectCatalogController` 提供来源扫描、重扫、差异摘要、模块/语义/敏感数据证据及只读历史关联核对；旧手工执行和投影维护入口已退场，正常调用进入业务方法/API 受控 Console。

### API 市场

API 市场是外部 API 的发现与项目接入目录，由 `reachai-capability-service` owning：

- `capability_external_api_source/provider/entry/version/operation` 保存来源、提供方、不可变版本和 Operation 契约。
- `capability_project_external_api` 与 `capability_project_external_api_operation` 保存项目接入意图和固定目录版本。
- 公共管理路径是 `/api/api-market/**`，由 Control 保持平台会话边界后委托 Capability。
- API 市场不保存第三方调用密钥，也不直接执行 HTTP；凭据、GraphSpec 与真实调用仍归 Workflow/Runtime。

详见 [API 市场产品与架构契约](./architecture/api-market.md)。标准 Agent Skill 包是“怎样完成工作”的说明资产，不是 API/Capability 的别名；两者的依赖只通过稳定引用和发布就绪检查协同。

## 仍待补齐

- SDK 能力同步已具备快照和差异表，但真实业务下的评审策略、冲突处理和回滚体验还需要继续产品化。
- 扫描链路和 SDK 链路都能进入能力目录，后续需要更明确的优先级：新系统优先 SDK，历史系统保留扫描。
