# 产品

ReachAI 是面向 Java 企业系统的 AI 能力中台，让员工在原业务页面或自己的 AI 工具中查询数据、填写表单和办理业务，同时保留企业身份、权限、操作确认与审计。

## 三个入口，一套治理

| 入口 | 用户做什么 |
| --- | --- |
| 业务系统中的 AI 助手 | 在已有页面对话，携带当前用户与页面上下文，执行显式注册的页面动作 |
| 员工自己的 AI 工具 | 从业务系统生成个人连接，以本人身份调用已开放的业务能力 |
| ReachAI 管理端 | 接入系统、维护能力、编排和发布 Agent / Workflow，查看运行、审批与评测 |

开发人员负责接入系统、开发 Agent / Workflow / Skill；管理人员负责上线运营、查看使用情况、审批写操作和管理调用权限；平台管理员维护账号、平台配置和资源。普通员工通过业务系统身份使用 AI，无需成为平台管理用户。

管理端按身份分成开发人员、管理人员、平台管理员三个工作台。侧栏只显示当前身份的菜单；拥有多个身份的账号通过左下角的「切换角色」按钮切换工作台，侧栏收起时保留切换图标。平台管理员拥有全部权限，默认看完整菜单，也可以切到其他身份预览。切换只改变菜单和概览，不改变权限：权限仍是账号全部角色的并集，从链接打开别的工作台的页面时侧栏会自动切过去。每个账号还有一个「我的」身份（我的首页、平台 AI 连接、我的记忆），没有管理端角色的账号登录后直接进入「我的」。菜单定义见 `ai-admin-front/src/components/common/sidebarWorkspaces.ts`。

普通员工不需要 ReachAI 账号：在业务系统的 AI 对话面板里点「在浏览器里管理」打开员工个人页（`/my/ai-tools`），分接入与体验、我能办的事、访问凭据、任务记录、我的审批、我的助手和我的记忆几页。「我的助手」是全屏对话，和业务系统里的是同一个 Agent、同一个身份：个人页登录换取短时对话令牌，令牌内容全部来自打开个人页时对话面板的已验证身份，不会长于个人页登录。记忆与对话面板里的是同一份。

## 核心对象

| 对象 | 含义 |
| --- | --- |
| 项目与实例 | 接入的业务系统及其运行实例，承载来源、环境与凭据 |
| 业务方法 | 业务系统明确开放的 Java 操作 |
| HTTP API | 有明确请求、响应和来源的 HTTP 操作 |
| Workflow | 由 GraphSpec 描述、可版本化发布的业务流程 |
| Agent | 理解意图并从已发布白名单中选择 Workflow 的智能体 |
| 标准 Skill | 经过治理、按精确版本绑定或下载的标准 SKILL.md 包 |
| 运行与 Trace | 身份、目标版本、调用、结果、确认和失败的可追踪事实 |

Capability 是业务能力的统称，Tool 是调用协议和运行投影。两者不构成需要用户重复维护的资产。记忆是 Agent 的能力；知识库、模型和业务索引提供支撑资源。

## 主流程

1. 接入业务系统，注册项目、实例和能力来源。
2. 同步契约并处理变化，将明确开放的操作接纳为业务方法或 API。
3. 在 Workflow Studio 编排、验证和发布流程，再加入 Agent 的可调用白名单。
4. 通过业务页面、员工工具或开放协议使用，按真实身份和权限执行。
5. 从运行定位问题、加入评测，并把可复用经验沉淀为 Skill 或 Workflow 草稿。
6. 管理人员在「AI 使用情况」按人、按 AI 工具（业务系统内对话、Claude Code、Codex 等）查看谁在用、办了哪些事、写操作审批结果和沉淀的 Skill。

真实业务校验和最终鉴权始终由业务系统负责。平台不凭模型输出、前端参数或能力目录中的展示状态授予执行权。支持范围见[当前边界](status.md)。
