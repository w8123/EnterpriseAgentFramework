# 原理：ReachAI 由哪些部分组成

> 适合：要部署、排障或二次开发 ReachAI 的开发者和平台管理员。读完你会知道 ReachAI 有哪几个服务、各管什么、一次提问在它们之间怎么流转。

## 整体图

```text
 业务系统页面（助手）   员工的 Codex / Claude Code   ReachAI 管理台
            │                     │                       │
            └─────────────┬───────┴───────────────────────┘
                          ▼
                 ┌──────────────────┐
                 │  Control 控制服务  │  所有外部请求的入口：登录、令牌、MCP、审批
                 └────────┬─────────┘
        ┌─────────────┬───┴─────────┬──────────────┐
        ▼             ▼             ▼              ▼
   Runtime 运行    Capability 能力   Knowledge 知识   Model 模型
   Agent、Workflow  业务方法目录、    资料、检索、     对接各家大模型
   运行记录、自动化  调用业务系统      记忆检索
                      │
                      ▼
               业务系统（SDK）
```

所有服务共用一个 MySQL。知识库向量检索用 Milvus（可选），文档解析用 Docling（可选）。

## 五个服务各管什么

| 服务 | 通俗地说 | 出问题时的表现 |
| --- | --- | --- |
| Control（控制服务） | 大门和前台。管理台登录、助手令牌、员工 MCP 连接、写操作审批、权限检查都在这里 | 打不开管理台、助手加载失败、员工连不上 |
| Runtime（运行服务） | 干活的。Agent 理解问题、规划步骤、执行 Workflow，记录每次运行；自动化任务也在这里 | 助手不回答、回答一半中断、运行中心没记录 |
| Capability（能力服务） | 业务系统的通讯录。记录每个业务系统注册了哪些方法，真正去调用业务系统 | 业务能力目录为空、调用业务方法失败 |
| Knowledge（知识服务） | 资料库管理员。文件解析、切分、向量检索 | 知识库上传后解析不了、检索不到 |
| Model（模型服务） | 模型总机。统一对接 DeepSeek、通义、OpenAI 等，管理 Key | 所有 AI 回答都报错 |

外部请求只进 Control，Control 验证身份后再交给对应的服务，其他服务不直接对外。

## 一次提问怎么流转

以员工在芋道助手里问「罗技无线鼠标还有多少库存」为例：

1. **Control**：验证助手令牌，确认是哪个员工、哪个 Agent、哪个页面。
2. **Runtime**：Agent 通过 **Model** 理解问题，决定先调用「查询产品」拿编号，再调用「查询产品库存」。
3. **调用权限检查**：确认员工的角色允许调用这两个能力。
4. **Capability**：带着签名和员工身份，调用芋道的 `/reachai/**`。芋道的 SDK 验签、还原员工身份，执行查询。
5. **Runtime**：拿到结果，通过 **Model** 组织成回答，写入运行记录。
6. **Control**：把回答返回给助手。

员工在自己的 Codex 里调用时，跳过第 2 步的 Agent 规划（规划由员工的 Codex 做），其余一样。

## 数据放在哪

| 数据 | 在哪 |
| --- | --- |
| 账号、项目、Agent、Workflow、运行记录、审批 | ReachAI 的 MySQL |
| 模型 API Key、项目凭据 | ReachAI 的 MySQL，加密保存 |
| 知识库文件和向量 | 文件存储 + Milvus |
| 业务数据（订单、客户、库存） | **始终在业务系统里**，ReachAI 只在调用时临时经手，不另存一份 |
| 业务系统的项目凭据 | 业务系统本机的凭据文件 |

## 排障时从哪看起

- 先跑 `reachai doctor`（容器安装），或看管理台「开始使用 → 系统体检」。
- 按上面「出问题时的表现」判断是哪个服务，再看它的日志：`reachai logs <服务名>`。
- 具体某次提问出错，去「运行中心」找到这次运行，看失败在哪一步。
