# BMAPI-2B 业务方法目录与详情规格

更新时间：2026-09-16。状态：主任务已确定本批规格；实现与验收待执行。前置 BMAPI-2A 已通过代码与模块验证；真实数据库升级、SDK 同步及完整调用路径仍未验收。

统一边界见[实施基线](./业务方法与API重构实施基线.md)，当前位置见[实施进度](./业务方法与API重构实施进度.md)，复用与分期见[设计决策](./业务方法与API重构设计决策.md)。

## 1. 用户任务与完成点

关联 U1 第 2 步和 U2 第 1–2 步：Java 开发者能找到自己明确开放的方法；实施人员能按项目和业务用途查找，读懂输入、返回、操作影响和当前来源状态。

当前混合目录主要按接入方式筛选，读取 DTO 尚未输出 2A 的明确资产类型。本批交付独立的业务方法读取接口、目录和详情，复用现有资产及调用投影，不建立另一份可写目录。

本批完成点是“准确找到并看懂”，试调用入口由 2C 实施，Workflow 选择与映射由 2D 实施。不得用无实际动作的“试调用 / 用于 Workflow”按钮冒充这两个批次；现有可访问的具体使用位置仍可跳转。

## 2. 数据与读取接口

### 2.1 类型与身份

- 来源仍是 2A 已接纳契约的派生投影。只收录 `asset_type=BUSINESS_METHOD`；HTTP_API、UNCLASSIFIED 和 NULL 旧记录不混入。
- 类型限定在 Capability 服务数据库查询阶段生效，分页总数与记录使用同一条件。不得取混合分页后在前端过滤，也不得按 source、URL 或类名猜类型。
- 沿用当前 `name` 机器标识、`qualifiedName` 和项目归属；不新造方法 ID，不重建表、不迁移 Workflow 引用。
- 已接纳但来源漂移、移除或停用的方法保留当前可读取的诊断状态；不将“仅列出 READY”作为默认查询。未接纳候选继续通过既有变化入口处理。

### 2.2 公开契约

| Control 公共入口 | 参数与结果 |
| --- | --- |
| `GET /api/business-methods` | `current`、`size`、`keyword`、`enabled`、`projectId`；返回 `records/total/current/size/pages`，类型固定 BUSINESS_METHOD |
| `GET /api/business-methods/{name}` | 读取当前业务方法；不存在或当前不是业务方法时返回 404；名称按单一路径片段编码 |

- `keyword` 覆盖标题、稳定标识和业务说明。分页边界沿用现有 1 起始、每页最多 100 条；排序稳定，搜索与范围改变回到第一页。
- Capability 提供对应的 `/internal/capability/business-methods` 与 `/{name}` 只读 owner 接口；Control 通过签名 client 调用。`/api/tools/**` 保持兼容消费者的既有语义。
- 以专用读取应用层组合现有 `CapabilityToolCatalogService` 查询、参数解析、关联和 `CapabilitySourceContractGuard` 状态。可提取共享查询 / DTO 映射，避免复制整套 controller、投影生成或同步逻辑。
- 返回安全的类型化目录字段，至少包含 `assetType`、`name`、`qualifiedName`、标题 / 说明、项目、输入与返回、操作性质、enabled、来源一致性及现有展示所需声明信息。可以复用现有字段结构，但资产类型必须明确，字段含义保持一致。
- 不为本批增加凭据读取或输出。不将未知参数、返回、示例或运行成功次数补造成事实。

## 3. 读取权限与必要支撑

- 平台会话是公共入口身份源。复用现有 `PLATFORM_READ` 和项目资源授权；项目 ID 由 owner 解析为可信项目身份后校验。未指定项目的跨项目读取需要现有全局授权，不能退回全量可见。
- 详情通过 owner 返回的真实归属校验权限，不能相信前端提供的 projectId。无权限、归属不一致和上游不可用不返回详情字段，也不伪装为空目录。
- 签名传输与 owner 验证复用已有机制，仅增加必要的精确读取路径。不要为目录读取改变 SDK 注册或 Runtime 执行授权。
- 当前 A2d0 WIP 已保护 catalog 和 `projects/by-id` 读取，但历史交接记录指出 `CapabilityProjectOnboardingClient` 的签名兼容性缺口。它是本批真实读取依赖，允许核对这几条路径与所有直接 by-id 调用者，并修复被现行过滤器阻断的最小调用契约；先保留相关 WIP 差异基线，在结果中单列修改与证据。
- 不把这个依赖升级为恢复整个 A2d0。不得取消签名、设置宽泛匿名白名单、伪造平台身份或修改真实用户授权来通过测试。若现有调用者缺少可合法传递的身份，应回报具体调用链与选择，由主任务补设计；其余独立的类型查询与 UI 工作可继续。

## 4. 页面与交互

### 4.1 导航和范围

- 新增 `/business-methods` 路由与“业务方法”入口，路由采用现有 PLATFORM_READ 和 `usePageProjectScope` 契约。
- 在“AI 资产”中增加业务方法主入口，紧邻现有能力目录。现有 `/capability` 仍是混合只读聚合入口，不整体改名或重定向，以便 API 与未分类旧记录仍可访问；这是过渡读取入口，最终导航在 API 路径与 BMAPI-5 一起收口。
- 本批不改 API 市场、项目 API 扫描或 Workflow 导航。可以从新页次要链接进入现有能力目录，并说明未分类旧记录的去向。
- 复用侧栏已确认项目范围，页面显示当前范围；不要再设置第二个与全局范围冲突的项目选择器。范围未确认 / 无权 / 项目列表失败时不发无项目条件的请求。
- 搜索或分页过程中切换范围、关闭详情、退出或切换账号后，迟到响应不得覆盖新状态；列表与详情均须守住请求归属。

### 4.2 目录

- 首屏以名称和一句业务用途为主；同时展示稳定标识、所属项目、操作性质和来源状态。Java 类名、HTTP 传输地址等实现细节放到详情技术区。
- 筛选提供名称 / 标识 / 说明搜索和“启用状态”。`enabled` 不叫“可用状态”；READY 只说明来源契约一致，不等同于已授权或真实调用成功。
- 每行有明确的“查看详情”入口，可键盘操作。正常、加载、无数据、无筛选结果、读取失败、403、上游不可用应有不同反馈与适用的重试动作。
- 空目录指向既有项目接入入口；未分类记录指向能力目录。不要用全站 0 指标、假运行指标或推广卡片填满页面。

### 4.3 详情

- 打开时通过专用接口重读当前方法，防止旧列表内容在类型或契约变化后继续充当详情；请求失败不将旧数据呈现为已验证。
- 延续现有居中双栏检查面板：输入 / 返回优先，来源与调用条件常驻；窄视口合并为一个可滚动区域。保留标题、关闭、刷新、返回焦点和键盘可达行为。
- 输入显示必填、位置、类型、嵌套字段、说明以及来源已声明的默认值 / 示例 / 约束；输出显示实际声明的返回字段和类型。缺少结构明确写“未声明”，不推导假 JSON Schema 或执行示例。
- 操作性质、声明超时 / 重试 / 角色、来源一致性分别显示；SDK sentinel 值仍按现有语义显示“未单独声明”。声明角色不当作当前用户已获权限。
- “使用位置”复用现有项目授权引用接口，保留 COMPLETE/PARTIAL/UNKNOWN 和失败状态。仅完整证据且无引用才展示“尚未被引用”；跳转具体 Workflow / 发布对象。
- 技术信息支持检查稳定标识、Java 声明、实际传输入口和来源信息；只显示存在的字段。复制输入契约沿用真实声明格式，不将其标注为可直接执行的请求。
- 复用 `CapabilityParameterTable`、参数拆分、状态与引用语义。详情可通过显式 loader / 展示上下文复用现有面板，或提取共享只读内容；不复制完整现有对话框，也不让业务方法详情退回不限定类型的 `/api/tools/{name}`。

## 5. 实现范围

- Capability：只读查询 / 映射 / 专用内部 controller、必要精确签名读取规则、相关测试。
- Control：业务方法公共读取 facade、复用的 owner client 与项目授权组件、必要 by-id 签名调用兼容及测试。
- 前端：方法 API/types、列表与详情、路由与单项侧栏入口、必要共享组件提取、相关测试；同步 DESIGN / UX-CONTRACT 中直接受影响的交互约定。
- 不修改 Runtime 执行、SDK 扫描、类型来源接纳、数据库 schema 或真实权限；2A upgrade SQL 仍不在本批自动执行。
- 遵循 frontend-design 与 frontend-design-premium 技能，读取 `ai-admin-front/DESIGN.md`、`UX-CONTRACT.md` 及 canonical UI resolution；沿用 WorkbenchPage、PageHeader、FilterBar、DataTableShell、StatusTag 与主题 token。不要扩展到全站样式治理。

## 6. 必须提交的验证证据

| 层次 | 场景与期望 |
| --- | --- |
| 持久化查询 | 混合方法 / HTTP_API / 旧未分类数据，类型筛选在分页前生效；总数正确；同名不同项目、搜索、停用 / 漂移记录准确；详情拒绝非方法 |
| Control / owner 合同 | 全局与项目读取、项目归属不一致、无权限、404、上游故障；Control 实际生成的签名请求与 owner 精确路径验证契约一致；受影响 by-id 调用者不回归 |
| 前端目标测试 | 范围与账号切换、迟到响应、详情重读 / 关闭、非方法 404、嵌套输入与返回、引用未知 / 失败、筛选和分页；避免仅镜像组件实现的测试 |
| 构建与守卫 | 相关 Maven 模块目标测试 / 必要模块验证；前端 build；相关架构守卫、diff 与新增文档链接 / UTF-8 检查 |
| 浏览器 | 桌面和窄视口的列表 / 详情、空态、失败重试、滚动与键盘关闭 / 焦点；保留截图或可复核的简短操作记录 |

允许隔离 fixture 支持页面验收，但必须在结果中标为模拟数据；H2、HTTP 合同测试、模拟浏览器与真实开发环境分开记录，不把前者称为 SDK/数据库/真实外部调用验收。不能因环境缺口跳过可独立完成的代码、模块验证和模拟页面检查。
