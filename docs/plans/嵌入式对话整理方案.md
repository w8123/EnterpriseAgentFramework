# 嵌入式对话整理方案

> 2026-10-17 起草，用户同意按方案推进。依据：[平台定位与架构总览](../01-平台定位与架构总览.md)。目标是让终端业务用户在业务系统里真正用上 Agent，以芋道 ERP（yudao.w8123.com）作为验收现场。

## 2. 目标形态

- **开发人员**在业务系统里只做两件事：后端实现一个「当前登录用户是谁」的解析器，前端加一段引用脚本。
- **运营人员**在 Agent 的「嵌入」页完成其余配置：允许哪些业务系统嵌入、来源域名、令牌有效期，复制接入代码，查看这个 Agent 的嵌入会话。
- 来源白名单仍属于项目（一个业务系统一组域名），但在 Agent 嵌入页可以直接编辑，需要 `embed:manage` 权限。
- 白名单同时驱动 CORS：Control 对 `/api/embed/**` 只放行当前生效白名单里的来源，不再需要改服务器配置。
- 浏览器里不出现任何项目密钥；页面注册改用嵌入令牌鉴权。

## 3. 分批

### E1 鉴权收口（后端 + SDK）
- 页面注册改为 `Authorization: Bearer <嵌入令牌>`，从令牌里取项目和来源，不再接受匿名或浏览器端签名；SDK 删除 `pageRegistry.appSecret`。
- Agent 图同步要求和心跳一样的项目签名（Control 入口校验后再转 Runtime）。starter 补上 `syncOnStartup` 的实际调用，否则删除这个配置项（默认：补上调用）。
- Control 嵌入 CORS 改为按白名单动态放行，带缓存；`reachai.embed.cors.*` 保留为额外放行项。
- 不改表结构。

### E2 Agent「嵌入」页（管理端）
- Agent 编辑页新增「嵌入」分区：选择业务系统（项目）→ 允许嵌入开关（写该项目的 allowedAgentIds）、来源域名、令牌有效期；一键「检查来源」（模拟一次换令牌和 CORS 预检，告诉用户哪一步不通）。
- 生成接入代码：后端解析器示例、前端引用片段（含 Agent ID、项目编码、脚本地址）。
- 嵌入会话审计按 Agent 过滤，入口移到这里；项目详情只保留页面和页面动作（开发人员的东西）。
- 管理端站点提供 `/sdk/embed-chat/reachai-chat-embed.umd.js` 和 `style.css`，构建和部署时一起发布（不能用 `/embed/`，Nginx 把它转给 Control）。
- 同步更新 `docs/01` 模块边界表里的嵌入归属说明。

### E3 starter 嵌入接入点 + 芋道接入
- starter 新增 `ReachAiEmbedPrincipalResolver` 接口；业务系统提供这个 Bean 时，自动暴露 `POST {context}/reachai/embed/token`，用当前登录用户换嵌入令牌（JDK8 兼容）。
- 芋道后端实现解析器（LoginUser + 租户 + 角色编码）；芋道前端（yudao-ui-admin-vue3）在布局里挂右下角对话入口。
- 在 Agent 嵌入页给 `yudao-erp` 配置来源 `https://yudao.w8123.com`、允许 `erp-assistant`（通过产品界面或 API，不直接写库）。
- 部署 ReachAI 和芋道，更新芋道接入指南和补丁。

### E4 验收
- 用 admin 登录芋道，在 ERP 页面打开对话：问库存得到与芋道一致的答案；「我的记忆」可查看和删除（补上记忆 M3 遗留的芋道端验收）。
- ReachAI 里能在 ERP 助手的「嵌入」页看到这次会话和运行记录。
- 负例：非白名单来源换令牌被拒；无令牌调用页面注册返回 401；无签名调用图同步返回 401。

## 4. 影响与风险

- 线上库：E1–E3 预计不改表结构；白名单配置走产品接口写入，部署时会说明。如果实现中发现需要 SQL，会单独请你确认。
- 兼容：浏览器端 `pageRegistry.appSecret` 的旧写法失效（目前没有业务系统在用）。
- 服务器内存紧张，芋道前端和后端各需要重新构建部署一次。
- 每批一个 PR 合并到 dev，经「部署项目到宝塔」线程上线。
