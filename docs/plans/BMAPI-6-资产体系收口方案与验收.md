## 目标与边界

- 业务方法与 API 分别拥有稳定身份、源契约、接纳决定和资产读取模型；旧能力目录不再是产品入口或第三套资产。
- SDK 声明、Controller、OpenAPI、市场分别是来源机制。资产类型由明确调用契约决定；同一 Java 实现的双重声明保留关联、独立契约。
- 来源观察 → 接纳资产 → 派生调用定义形成单向关系。业务方法目录、试调用条件和 Workflow 选择不能把 Tool 投影作为源资产事实。
- Workflow 引用稳定源资产并在发布时固定契约；Runtime 保持授权、风险、确认、去重、UNKNOWN 原记录查询和 Run/Trace。Agent 继续消费已发布 Workflow。
- 保持现有五服务、SDK 技术身份及同库所有权边界。注册签名凭据由现有 SDK 协议 owner 管理；运行连接、调用结果及发布 pin 保持各自 owner，不跨服务直接访问表。
- 合法 PAGE_ACTION、标准 Agent Skill、MCP/A2A/Embed 和 SDK 发现/同步继续可用；旧独立 Tool/Composition/Interaction 资产的合法职责分别归入方法/API、Workflow 和交互/页面动作，不留第二套业务模型。
- 新库直接采用目标 schema；不为旧未分类行、旧资产维护入口或历史引用建设双读/双写兼容。SQL 对现有开发库的影响明确说明，实际执行仅针对核验后的目标库表；不清空无关业务数据。
- 本批不提交、推送或发布部署，不恢复暂停的 A2d0，不调用客户业务，不重放旧未知写调用。现有 WIP（包括进度中的本人查看反馈）保留。

## 产品与代码目标

| 层次 | 目标 |
| --- | --- |
| 导航 | 业务方法、API 为资产入口；项目负责接入/同步/来源异常；详情负责变化和具体引用；删除旧能力目录、旧空态去向、面包屑和导航回退 |
| 前端 | BusinessMethodInfo / businessMethod API / 独立业务方法页面；复用输入输出、引用、Overlay、主题、菜单键盘及状态原语，保留列表上下文 |
| Capability | businessmethod/httpapi 领域明确；同步事务先形成业务方法资产，再派生调用定义；变化、移除、回滚、相同内容重报均维护唯一资产 |
| Runtime | 资产类型/身份/契约引用明确；发布和执行核对 owner 事实；连接/凭据变化使验证失效；不静默使用最新契约 |
| 退场 | 删除无合法消费者的旧资产、Mapper/Service/路由/解析分支/种子/文档；技术 Tool 投影只保留明确消费者与派生职责 |

## 实施顺序

1. 固定当前字节和去留映射；建立业务方法资产、契约修订与 SDK 传输绑定，接入同步/评审/移除/回滚事务。
2. 方法目录、试调用上下文和 Workflow 引用切换到资产 owner；前端领域类型和页面收口；项目/资产变化与使用位置导航一致。
3. Runtime/Control/开放协议直接消费者适配，删除旧独立资产执行与组合路径；API 保持其独立事实并核对多来源、验证和变更流程。
4. 完成新库/开发库 SQL、静态守卫、目标与受影响测试、构建、浏览器和真实受控调用；逐项审计并更新进度。

顺序用于控制依赖，不缩小最终目标。实施发现新的直接依赖时在本文件说明并继续完成，不新增逐批审批。
