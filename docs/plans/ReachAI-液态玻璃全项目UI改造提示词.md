### 5. 视觉方向与材质层次

整体气质：清透、安静、精细、紧凑。保留 ReachAI 的品牌、中文业务文案和工作台属性。

浅色以柔和的中性浅底为主，背景少量引入当前品牌色。玻璃边界要有细腻内高光和适量阴影，能感知表面厚度。暗色采用中性烟色表面，保持清晰的文字和状态色。

把材质分为以下用途，名称可以映射现有 token 和 class：

| 层次 | 适用位置 | 材质要求 |
| --- | --- | --- |
| 页面底层 | 页面与工作区背景 | 安静、低频的品牌透色，长时间停留不疲劳 |
| 导航和操作层 | 侧栏、浮动工具栏、分段切换 | 最清晰的玻璃轮廓、边缘高光和轻微折射 |
| 内容承载层 | 表格、表单、指标、详情、日志 | 更高不透明度，轻边界，稳定的阅读底 |
| 弹出层 | 菜单、Popover、Dialog、Drawer | 相对背景有明确层次，内容区对比度稳定 |
| 临时交互层 | 拖动、选中、按压反馈 | 短促而轻微的形变或高光反馈，及时结束 |

具体要求：

- 玻璃主要体现在导航和操作区域。内容面板可以保持材质一致，但大段文字、表格和代码不参与折射。
- 高光集中在边缘，文字与图标层保持清晰；滤镜放在独立背景层或伪元素上。
- 使用同一套圆角尺度。浮动工具栏、分段器可使用胶囊形；表格、输入框、节点和表单保持适合各自任务的形态。
- 保留紧凑的信息层级；页面标题、筛选、列表和主要操作能在首屏形成清晰关系。
- 主要动作清楚突出，次要动作收敛；危险和警告状态保留语义颜色，不能随品牌换色失去含义。
- 系统字体优先，保证 Windows 和中文显示。代码、JSON、Trace 标识使用合适的等宽字体。
- 普通文字对比度以 4.5:1 为底线，大文字和必要图形边界以 3:1 为底线；检查合成后的真实背景。
- 动效优先使用 `transform / opacity`，常用反馈约 120–240ms，遵守减少动态效果设置。
- 不使用持续晃动、全屏流光或大面积鼠标跟随；不将内容区整体模糊。

### 6. 必须形成的可复用体系

#### 6.1 Token 与样式组织

收敛为「品牌原语 → 语义 token → 材质与组件映射 → 页面布局」：

- 品牌原语：现有 7 套品牌色保留，明暗模式与品牌解耦。
- 语义 token：页面、内容、控件、弹层、边界、文字、状态、阴影、高光、圆角、间距、密度、动效。
- 材质层：统一处理透明度、模糊、饱和度、边缘高光、可选折射、降级和性能开关。
- Element Plus 映射层：集中映射 `--el-*`，结构性修补保持明确且数量可控。
- 页面样式：布局、区域尺寸与必要的业务展示差异，避免重复定义品牌色、玻璃底和阴影。

保留已有语义变量的有效引用关系；要淘汰旧别名，先查全仓消费方、迁移并验证。不要任意重命名已被 SDK 和页面使用的 token。

清理主题入口中的重复明暗样式和互相覆盖的旧规则。按具体责任拆分文件，控制选择器优先级，避免通过不断追加 `!important` 解决冲突。

#### 6.2 公共组件与页面类型

优先统一已有公共组件。让列表页、详情页、表单页、工作区页和调试页形成可复用的组合方式。

重点覆盖：

- 页面外壳、返回与面包屑、紧凑页头、项目范围选择。
- 搜索筛选条、工具栏、批量操作、Tab/分段切换。
- 内容面板、数据表格、分页、状态标签、指标条。
- Dialog、Drawer、Popover、Dropdown、Tooltip、MessageBox。
- 输入框、选择器、日期与时间选择、开关、树、上传、步骤条。
- 代码与 JSON 阅读、空状态、加载、校验失败、请求失败、无权限状态。

组件必须保留或正确转发业务使用的 `props`、`v-model`、事件、具名/作用域插槽、attrs 和必要 ref 能力。封装 Dialog、Drawer 等组件时，验证焦点、关闭行为、尺寸和挂载位置。

只抽象有实际复用场景的能力。不要给每一种普通 Element Plus 控件套一个没有价值的新组件。

#### 6.3 主题与偏好

- 浅色是默认主体验，7 套品牌色全部可用，沿用现有合法保存值和品牌语义。
- 审计并补齐暗色模式。若恢复暗色入口，必须先让公共组件与覆盖范围内页面达到一致、完整可用的标准；仅删除浅色锁定不算完成。
- 明暗变化同步维护 `data-theme` 与 Element Plus 的 `html.dark`，正确处理持久化与首屏初始化，避免刷新后闪色或还原。
- 沿用并统一密度能力；公共组件不要用写死的默认密度把用户选择覆盖掉。保留确有用途的页面级密度覆盖。
- 对已有减少透明度规则提供一致支持；关闭材质增强时仍保持清楚的边界和可读性。
- 在现有外观入口集中呈现必要偏好，不新增散落在业务页面的玻璃参数设置。

#### 6.4 SDK 与共享对话的隔离

- 管理端、Agent 调试和嵌入式对话复用适合共享的材质与主题规则。
- 保持 SDK 现有主题 API、预设名称、事件和资源路径兼容；不要重命名 `eaf.*`、`Eaf*` 或 `X-EAF-*` 等技术标识。
- 管理端状态变化不能越过 SDK 的显式主题配置；嵌入组件不能修改宿主页面的 `html`、`body` 或全局主题。
- 使用命名空间、容器作用域或原有隔离机制，防止全局 CSS 泄漏到宿主业务系统。

- 已经迁到弹窗的版本能力保持现有工作流，不恢复已删除的独立版本页。
- 知识库详情中已经收拢的文件、检索、分析和设置保持现有结构；不恢复重复菜单。
- Logo 与现有品牌资产继续使用，不因追求 Apple 风格替换为 Apple 图标、商标或整套系统图标。

### 9. Workflow Studio 和复杂工作区专项要求

Studio 使用独立布局，不强行套普通页面标题卡和列表页容器。

重点检查：

1. 顶栏、画布工具栏、添加入口、AI 编辑条、状态栏和配置面板使用同一主题体系。
2. 玻璃效果集中在悬浮操作区域；节点名称、字段、连接端口、选中边界、运行状态和错误信息清晰。
3. 节点拖动、连线、缩放、平移、多选、键盘、菜单、折叠与面板切换不受滤镜和遮罩影响。
4. 边、节点、浮动控件和弹出层有可控的层级，避免控件遮住连接手柄或吞掉指针事件。
5. 节点宽高或内部布局变化后，检查端口和连线定位，正确使用现有 Vue Flow 更新机制。
6. 配置面板滚动范围合理，底部操作可达；复杂字段保留明确分区和校验提示。
7. UI 重构不能改变 GraphSpec 的可执行语义、序列化、参数绑定、版本引用和发布校验。
8. 验证添加/编辑节点、保存、AI 候选预览/应用、发布校验、Agent Workflow-as-Tool 配置与调试之间仍一致。
9. 多节点场景仍可流畅操作；不为每个节点分配持续动画、鼠标监听或独立的重型渲染器。

G6 图、模型调试、Agent 调试和嵌入对话等复杂工作区也按各自任务处理滚动、尺寸、层级和主题，不统一压成列表页。

### 10. 兼容性、性能与可访问性

- Chrome、Edge 优先验收；有条件时检查 Firefox 和 WebKit/Safari，明确实际测试过的浏览器。
- 基础体验使用稳定的 CSS 材质层；SVG 折射或其他增强采用渐进启用与可靠降级。不能只凭 `CSS.supports` 宣布折射可用。
- `backdrop-filter`、SVG filter、祖先 `opacity/filter/transform/isolation` 和层叠上下文的组合要在实际 DOM 中验证。
- 表格固定列、吸顶表头和可编辑单元格保持足够不透明，不能透出重叠文字；横向滚动不破坏边界与操作列。
- Teleport 到 `body` 的下拉、日期选择、Tooltip、Dialog、Drawer、MessageBox 等同样消费正确主题，避免明暗错配与被裁切。
- 不对所有行、卡片和节点都加独立模糊；限制同时出现的重型效果，避免不必要的重绘和持续计时器。
- 事件监听、Observer、动画和渲染资源能正确释放；反复切页与开关弹窗后不持续增长。
- 保留键盘导航、清晰焦点、可读标签、图标按钮的无障碍名称；弹窗焦点进入与返回行为正确。
- 遵守 `prefers-reduced-motion`，支持减少透明度和必要的强制颜色降级。主题与密度设置在刷新后生效。
- 在相同机器、浏览器、数据与操作路径下对比改造前后响应，记录明显回退及修复。没有测量证据，不宣称固定帧率或性能提升。
- 主要检查 1440px、1280px、1024px 桌面宽度；补充 768px、390px 的可达性检查。狭屏可以折叠导航、切换面板或容器内滚动，页面不应出现无意义的整体横向溢出。

### 11. 执行阶段：分批交付并持续推进

#### 阶段 A：审计与选型

产出仓库/UI 现状、迁移矩阵、已有检查基线、候选开源对比和简短设计方案。确定玻璃层次、色彩、字号、密度、圆角、动效与复用落点。

#### 阶段 B：主题基础与公共样例

统一 token、材质层、Element Plus 映射、主题偏好与降级。选取一个真实列表页和一个真实弹窗验证；这个阶段用于确定公共方案，不作为全站完成的终点。

#### 阶段 C：布局与公共组件

完成所有布局模式、导航、页头、筛选、表格、表单与弹出层的公共能力。复查插槽、事件和已有权限表现，清理冲突规则。

#### 阶段 D：逐模块全站迁移

按页面类型与依赖关系迁移所有活跃页面，补齐复杂详情与表单。每批更新覆盖清单，验证公共变更是否影响已完成模块。

#### 阶段 E：Studio、复杂工作区与共享对话

完成特殊布局、画布、节点配置、调试、消息与嵌入场景，验证主题隔离和 SDK 构建。

#### 阶段 F：回归与收尾

完成主题/品牌/密度组合检查、浏览器走查、构建和相关测试；清理迁移完成后无引用的样式与临时代码，更新设计系统说明与第三方来源记录。

阶段完成后继续推进。遇到某个真实接口或账号阻塞，记录证据，先完成不依赖它的模块；最终明确哪些验收尚未完成。长任务中持续维护可续接的进度，不能把上下文限制当作整个项目已经完成。
