# 知识模块整理方案

> 2026-10-18 起草。依据：[平台定位与架构总览](../01-平台定位与架构总览.md)、[知识、模型与企业资产](../05-知识模型与企业资产.md)、[Workflow Studio 整理方案](Workflow%20Studio整理方案.md)。目标只有一个：运营人员建好知识库、传上文件之后，芋道里的 ERP 助手真的能用它回答制度类问题，查不到时如实说没有；页面上每个开关都真的生效。

## 1. 现状（dev 91587a81 + 线上只读核对）

线上数据：1 个知识库 `erp_policy`（ERP 仓储与售后制度）、1 个文件、1 个段落；没有任何 Workflow 用到知识节点；业务索引、标签、问题映射、命中记录都是 0 条。

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1 | 终端用户检索不到知识 | Runtime 知识检索按「用户 × 文件」授权过滤（`knowledge_user_file_permission`）；授权只在入库时发给导入人本人（`KnowledgeFileReadAccessService.grantPublishedImporter`），没有其他授权入口。线上唯一一条授权是平台用户 `1` | 芋道业务用户通过嵌入式对话提问时，知识库对他等于空；管理端「检索测试」不带用户过滤，所以测试能查到、真实对话查不到，问题被掩盖 |
| P2 | Agent 用不上知识库 | Agent 只能选 Workflow；知识只能通过 Workflow 的「知识节点」使用，要自己搭 用户输入 → 知识检索 → 模型回答 → 回复 四个节点。线上没有一个 Workflow 这样搭 | ERP 助手被问「退货政策」只能瞎答或说不知道 |
| P3 | 知识库「检索策略」大部分不生效 | Runtime 只用节点上的 TopK / 阈值 / 检索模式，没配就用全局默认（5 / 0.5 / hybrid），不读知识库上的设置；「直接返回」Runtime 根本不支持 | 运营人员调了参数以为生效了，其实没有 |
| P4 | 命中分析只统计管理端测试 | Runtime 检索固定 `recordHit=false` | 「运营概览」「命中分析」「低置信命中」「零命中段落」看不到真实用户的问题，做不了运营 |
| P5 | 标签、问题映射是摆设 | 检索引擎不读 `knowledge_tag`、`knowledge_question`；批量打标签对话框还是英文（Batch Tags / Preset / Group） | 7 个页签里有 2 个没有实际作用，徒增理解成本 |
| P6 | 知识库详情太散 | 详情页 7 个页签；上传文件要跳到另一个菜单「文件入库」再选一次知识库；检索测试在「实验室」里；列表里 Embedding 显示的是实例 UUID | 一件事要在三个菜单之间来回跳 |
| P7 | 切分不按标题 | `erp-faq.md` 有 4 个二级标题、747 字，入库后是 1 个段落 | 文件一大，回答会带进大量无关内容，命中也不准 |
| P8 | 业务索引放在「知识」下，但没有地方能用它 | 业务索引由业务系统 SDK 按项目同步；Runtime 只在节点输出里出现索引引用时回源，没有任何节点或 Agent 能检索业务索引；记忆整理时已决定它归「业务能力」 | 运营人员在「知识」里看到一个自己填不了、也用不上的东西 |

不改的部分：文档解析（Java Fast / Docling）、入库任务与失败回收、向量集合生命周期、个人记忆索引。这些是底层保障，本次只调整入口和展示。

## 2. 分批

### K1 让知识真的能被终端用户查到（Knowledge + Runtime + SQL）
> 状态（2026-10-18）：已完成代码，随知识模块 PR 合并部署。
- 知识库新增「谁能检索」：`全部调用方`（默认）/`仅授权文件`。`全部调用方` 时，Runtime 检索只校验知识库启用、段落启用、文件当前有效，不再要求逐文件授权；`仅授权文件` 保持现在的逐文件授权。管理端在知识库设置里显示这个选项和一句说明。
- 知识库上的检索设置真正生效：节点没填的 TopK、阈值、检索模式、Reranker、权重一律取知识库设置，再没有才用全局默认。删除「直接返回」及其阈值（Runtime 不支持，留着只会误导）。
- Runtime 检索记录命中（来源标记为对话），「命中分析」「低置信命中」「零命中段落」改为以真实对话为主，管理端测试可单独筛选。命中记录只存问题和分数，不存回答。
- SQL：`knowledge_base` 加 `access_mode`，删掉直接返回两列，`knowledge_hit_log` 加 `source`；对应升级现合并至 `sql/upgrade-20261019-consolidated.sql` 段落 10，现有知识库设为 `全部调用方`。线上执行前请你确认，先备份 `reach_ai`。

### K2 一键接入 Agent（管理端 + Runtime 模板）
> 状态（2026-10-18）：已完成代码，随知识模块 PR 合并部署。
- 知识库详情右上角加「接入 Agent」：选一个 Agent，平台按模板生成并发布一个「知识问答」Workflow（用户输入 → 知识检索（必须有依据）→ 模型按资料回答并注明出处 → 回复；没检索到时直接回复「资料里没有找到相关内容」），然后把它加入该 Agent 的可调用 Workflow 并发布新配置版本。生成的 Workflow 和手搭的一样，可以在 Studio 里继续改。
- 知识库列表和详情显示「被哪些 Workflow 使用」，没人用时提示「还没有 Agent 使用这个知识库」并给出「接入 Agent」按钮。
- 切分改进：Markdown / Word 按标题切分（标题作为段落标题），超过 Chunk 大小再按长度切；对已有文件提供「重新解析」即可生效。

### K3 知识库页面收拢（管理端）
> 状态（2026-10-18）：已完成代码，随知识模块 PR 合并部署。
- 详情页 7 个页签改为 4 个：**文件**（在页内上传，显示解析进度、失败原因和重试，点文件看段落）、**检索测试**（从实验室搬进来，默认用本库设置，并标出「终端用户能否查到」）、**命中分析**（合并运营概览和命中分析：真实问题、低置信、零命中段落）、**设置**（基础信息、模型、谁能检索、切分、检索策略）。
- 删除标签和问题映射（页面、接口和两张表），检索引擎本来就不用它们。
- 侧边栏「知识」只留「知识库」一项；「文件入库」并入详情页（旧链接跳到对应知识库）；「实验室 → 知识检索测试」删除。
- 列表：Embedding 显示模型名而不是 UUID，新增段落数和「使用中的 Workflow」列；文案去掉 Chunk、TopK 等英文术语或配中文说明。

### K4 业务索引归位、文档与验收
> 状态（2026-10-18）：已完成并在芋道验收通过（PR #37–#42）。
- 业务索引从「知识」菜单移走，放到「项目接入 → 项目详情」下的「业务索引」页签（索引本来就按项目由 SDK 同步）。页面写明它的用途和当前限制：Agent 还不能直接检索业务索引。代码和 SDK 不动。
- 更新 `docs/05-知识模型与企业资产.md`、`docs/architecture/knowledge-base-lifecycle.md`、`service-table-ownership.md`。
- 线上验收（芋道 ERP 助手）：
  1. 在 `erp_policy` 重新解析 `erp-faq.md`，确认按 4 个标题切成 4 段；
  2. 用「接入 Agent」把 `erp_policy` 接入 ERP 助手；
  3. 在芋道里问「电子产品签收后多少天可以无理由退货」→ 回答 7 天并注明出自《ERP 仓储与售后制度》；问「年假有几天」→ 回答资料里没有；问「鼠标有多少库存」→ 仍走库存查询；
  4. 知识库「命中分析」能看到这几条真实问题；
  5. 评测集「ERP 助手回归」加入退货、年假两条，对比实验全部通过。

## 3. 影响与风险
- K1 改变检索授权的默认值：原来只有导入人能查到，现在调用该 Agent 的所有用户都能查到。需要按人限制的知识库要改成「仅授权文件」。线上目前只有 `erp_policy` 一个库，内容是公开制度。
- K1、K3 有数据库变更（加列、删列、删 `knowledge_tag` / `knowledge_question` 两张空表），线上执行前逐条找你确认。
- 命中记录会保存终端用户的原始问题，只在管理端「命中分析」可见，权限沿用知识库读取权限。
- 服务器内存紧张，本次不新增服务、不加常驻任务；「接入 Agent」用现有 Workflow 和 Agent 发布接口完成。
