## 推进顺序

1. 3C-D R1：合法必填空对象、390px 作者操作及真实结果说明已复核，静态收口通过；该隔离代表范围已签收，整体缺口保持。
2. BMAPI-5A：按当前真实消费者闭合旧入口去留，实施直接接替/退场和必要协议回归；同一 U1–U4 不再维护第二份 Tool。
3. 整体角色任务与环境验收：检查最终可用的隔离 MySQL/独立服务/SDK 环境，完成真实签名与调用；能自主完成的在隔离资源中执行，必要外部环境信息再具体提出。
4. 最终复核：每项指向当前证据与真实限制，区分代码、验证和真实用户易用性结论；仍有必验项缺口时继续，不标 100%。

复杂 schema/认证、其他 HTTP 动词/循环图按具体已承诺场景判定，不能无限增加新功能拖延基线收口，也不能把既有真实需求归为“不支持”以删除验收。普通实现自主推进，产品边界变更须先有具体方案/影响；不自动恢复 A2d0 或扩建全平台范围/权限。

## 持续执行方式

主任务已启用本对话自动续办，既有执行窗口完成后由主任务自动读取结果、复核并下发下一具体批次。一次一个实施批次，主任务不重复测试，不依赖执行窗口的跨对话回传授权。状态未变化时不重复通知用户。

当前范围仍不包含提交/推送/真实部署、已有开发库升级、真实权限修改或客户系统写入；没有因此禁止新建可销毁的本批隔离验证资源。若最后需要外部环境或真实用户试用，提供已可审查的结果、缺少的信息和具体动作，不能把未做的步骤算完成。
