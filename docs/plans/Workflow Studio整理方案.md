# Workflow Studio 整理方案

> 2026-10-18 起草。依据：[平台定位与架构总览](../01-平台定位与架构总览.md)、[Workflow Studio 与 Runtime](../03-Workflow-Studio与Runtime.md)、[运行中心整理方案](运行中心整理方案.md)。目标有两个：让实施人员在 Studio 里改一个节点、跑一遍、发布，步骤更少、所见即所得；让 Workflow 在查不到东西时如实说「没找到」，而不是拿一个相近的结果冒充。

## 1. 现状（dev 68ad157b 核对）

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1 | 在芋道问「键盘」库存，返回的是鼠标，回答没有说明 | 运行中心验收记录；Workflow `product-stock-query`：用户输入 → 产品列表 → 模型参数提取 → 查库存 → 回答。根因见 §2 | 业务用户拿到错误数据却以为是对的，这是最伤信任的一类错误 |
| P2 | 连线条件里的「失败」「为空」「非空」只在画布上存在，运行时从不走这些连线 | 前端 `selectedEdgeConditionOptions` 提供 `error` / `empty` / `not_empty`；Runtime `edgeMatchRank` 只认路由 ID、`else`、`always`/`success`，节点失败直接结束整次运行 | 实施人员以为配了兜底，其实没有；Workflow 无法把「没查到」「调用失败」变成一句正常回答 |

| P6 | 「批量评测」和运行中心评测重复，而且用例不保存 | Studio「更多 → 批量评测」用例只在页面内存里，刷新即丢；运行中心已有按 Agent 保存的数据集和对比实验 | 两套评测，Studio 里那套做完就没了 |

调试抽屉、只读试运行、发布校验、AI 生成/修改 Proposal、版本记录这些能力本身可用，这次保留，只调整入口和展示。

## 2. 「键盘 → 鼠标」根因

线上核对（2026-10-18，部署线程只读排查，trace `d8795f5ff0b543dd924c67939aa815a8`）：

- 芋道 ERP 共 7 个产品，没有键盘；id 2 是「罗技 MX Master 3S 鼠标」。
- Supervisor 调用 `product-stock-query` v1.0.3 一次；五个节点全部成功。芋道日志显示 `erpStockPage` 收到 `{"productId":"2"}`。
- 参数提取节点的用户提示词是「请从以上产品列表中找出名称**最匹配**的一个产品，返回其产品编号」，`productId` 必填，没有「无匹配」的出口；模型于是挑了同属电子产品的鼠标。
- 回答节点只是模板 `{{ nodeOutput.query_stock }}`，不说明查的是哪个产品；Supervisor 转述时也没有指出名称不一致。
- 附带发现：运行记录里 Workflow 节点的输入输出摘要都是空（脱敏后不落库），这类问题只能去业务系统日志反查。这次不改，留到知识/运行治理时再评估。

不论具体是哪一步猜错，平台层面都缺两样东西：

1. **没有「没找到」的出口**：参数提取在缺少必填字段时只能让整次运行失败（P2），所以 Workflow 作者倾向于不设必填，模型就会挑一个最接近的值继续往下跑。
2. **回答不核对对象**：最后的回答节点和 Agent 都没有被要求核对「用户问的东西」和「查回来的东西」是否一致。

## 3. 分批

### W1 如实回答「没找到」（Runtime + 管理端 + 芋道 Workflow 配置）
- Runtime 支持「失败时」连线（条件值 `error`）：节点失败且没有另配错误策略时，如果有这条出边就沿它继续，失败信息写入变量 `lastError`（节点、错误码、固定的中文说明），节点结果记 `recoveredFromCode`，运行详情可见；没有这条出边时行为不变。
- 「结果为空」「有结果」连线（`empty` / `not_empty`）：按节点输出是否为空判断（空列表、空对象、`total=0` 或 `list/records/rows/items` 为空的分页结果、空字符串）；参数提取缺少必填字段时优先走「结果为空」。
- 发布校验：没有分支的节点，出边条件只能是 `always`、`success`、`error`、`empty`、`not_empty`，其他值报 `GRAPH_EDGE_CONDITION_UNSUPPORTED`，不再静默忽略。画布连线条件只列这些选项和分支名。
- 参数提取默认提示词改为：只能使用输入里明确出现或候选列表里精确对应的值，不允许取「最接近的」；字段可设「取值必须来自列表」（`optionsFrom` 列表表达式、`optionValueKey` 取值字段、`optionLabelKey` 名称字段），候选会写进提示词，模型给出的值不在列表里视为未提取到。
- Agent 回答规则（Supervisor 系统提示）加一条：工具结果里的对象和用户问的对象不一致时，必须明确说出来。
- 修 `product-stock-query`：产品名必填且必须来自产品列表；「为空」连线到回答节点「没有找到名为 X 的产品」。经部署线程用产品 API 更新并发布新版本，Agent 更新引用（不直接改库）。
- 把「键盘」「鼠标」两条问题加入评测集「ERP 助手回归」，期望分别是「说明没找到」和「返回鼠标库存」。

### W2 拆分主文件（管理端，行为不变）
- 22 种节点卡片合成一个 `StudioNodeCard` 组件，由节点元数据（图标、颜色、摘要行、路由口）驱动。
- 拆出 `StudioHeader`、`StudioPalette`、`StudioCanvasToolbar`、`StudioAiEditBar`、`StudioInspector`（草稿检查 / 流程变量）、`StudioPropertyPanel`；样式跟随组件搬走，公共样式进 `studio.scss`。
- 目标：`WorkflowStudio.vue` 只负责组装和状态连接，不超过 1500 行。现有守卫测试全部通过，新增节点卡片渲染测试。

### W3 属性面板直接编辑（管理端）
- 去掉「四张卡片 → 对话框」两步：选中节点后右侧面板直接显示三个页签「配置 / 测试 / 调试记录」，节点名称和描述放在配置页顶部；面板可拖宽，记住宽度。
- 选中连线时，条件只列出运行时支持的选项（默认、成功、失败、为空、非空，以及该节点的分支名），显示中文名，不再显示 `always`、`路由: 分组ID`。
- 文案清理：参数提取模式显示「按表达式 / 用模型提取」；Workflow 信息里 `keySlug` 改为「标识」并说明用途，「类型」改为下拉；画布左侧「画布规则」提示改为实际有用的快捷键说明。

### W4 运行与测试收口、清理与验收
- 删除 Studio「批量评测」抽屉及其组合式函数；在「更多」里改为「到运行中心评测」，跳到引用该 Workflow 的 Agent 的评测页（多个 Agent 时先选）。
- 「调试」按钮在草稿含业务方法或 API 时自动用只读试运行，按钮旁明确标出当前是「沙箱调试」还是「只读试运行」，不再只靠悬停提示。
- 更新 `docs/03-Workflow-Studio与Runtime.md`（连线条件语义、失败连线、取值必须来自列表）。
- 线上验收（芋道 ERP 助手）：问「键盘有多少库存」→ 回答说明没有这个产品；问「鼠标有多少库存」→ 数量与芋道一致；在 Studio 打开 `product-stock-query`，直接在右侧改回答节点文案 → 调试 → 发布 → Agent 更新引用；运行中心对比实验跑「ERP 助手回归」全部通过。

## 4. 影响与风险

- 线上库：预计不改表结构，也不需要种子 SQL。W1 的芋道 Workflow 调整走产品 API（保存草稿 + 发布），会产生新版本，可回退到旧版本。
- 兼容：已有 Workflow 里如果画过「失败 / 为空」连线，W1 之后这些连线会真正生效（以前被忽略）。发布前的校验会把它们列出来；上线前我会查一遍线上已发布的 Workflow 有没有这类连线。
- 模型调用：验收会调用几次模型（芋道提问和一次对比实验）。
- 每批一个 PR 合并到 dev，经「部署项目到宝塔」线程上线。
