# 角色、账号、权限整理方案

> 2026-10-24。基于 dev（2b789d78）代码核对。按批次实施，结果见本文末尾。延续 2026-10-17 的角色重设计（平台权限和调用权限分开），按新的产品方向（员工用自己的 AI 工具办业务、管理者看使用记录）补齐。

## 1. 四类人，两套权限

| 人 | 在哪里用 | 用什么账号 | 权限从哪来 |
| --- | --- | --- | --- |
| 开发人员 | ReachAI 管理端 + 业务系统代码 | ReachAI 账号 | 平台角色「开发人员」，**按项目**授权 |
| 运营人员 | ReachAI 管理端 | ReachAI 账号 | 平台角色「运营人员」 |
| 管理人员 | ReachAI 管理端 | ReachAI 账号 | 平台角色「管理人员」（**新**，替换原「审计员」） |
| 普通用户（员工） | 业务系统里的 AI 助手，或自己的 Claude Code / Codex | **业务系统账号**（如芋道），不登录管理端 | 「调用权限」按业务系统角色控制 |

另有「平台管理员」负责装平台、管账号和模型，拥有全部权限。一个人可以同时有多个角色。

## 2. 每类人能看到什么

| 功能 | 开发人员 | 运营人员 | 管理人员 | 平台管理员 |
| --- | --- | --- | --- | --- |
| 概览 | 开发视图 | 运营视图 | 管理视图 | 全部 |
| 项目管理、SDK 接入、同步诊断、页面动作、业务索引 | 读写（本项目） | 只读 | — | ✓ |
| 业务能力（Java 方法、HTTP API、变化评审、调试调用）、API 市场 | 读写（本项目） | 只读 + 调试调用 | — | ✓ |
| Workflow、Agent | 只读 | 编排、调试、评测、发布 | 只读 | ✓ |
| Skill | — | 查看、导入、绑定到 Agent | 只读 | ✓（含审核、发布） |
| MCP Hub（发布、员工可用、员工连接、调用日志） | — | 管理 | 查看 + 断开员工连接 | ✓ |
| A2A 互联（已冻结） | — | 管理 | — | ✓ |
| 知识库 | 只读（业务索引要用） | 读写 | 只读 | ✓ |
| 自动化中心 | 只读 | 管理 | 只读 | ✓ |
| 运行中心（对话、运行、Trace、评测） | 只读 | ✓ | 只读（看谁、用什么工具、做了什么） | ✓ |
| 业务用户、调用权限 | — | 管理 | 只读 | ✓ |
| 模型中心、模型调试台 | 只读 | 只读 | — | 管理 |
| 账号与角色、认证源、运行时用户映射、合规擦除、会话保留 | — | — | — | ✓ |

普通用户在业务系统的 AI 助手里看到：对话、我的记忆、「在我的 AI 工具中使用」（勾选系统、复制一行到 Claude Code / Codex、我的连接）。能调用哪些业务方法和 Workflow，由运营人员在「调用权限」里按业务系统角色配置。

## 3. 现在的问题（代码核对）

| 问题 | 证据 |
| --- | --- |
| 没有「管理人员」 | 只有「审计员」，概览把审计员当运营视图；看不到员工连接也不能断开 |
| 只读角色能看到写按钮，点了才报 403 | 知识库、业务索引、调用权限、业务用户、MCP Hub、A2A、项目列表/详情、Skill、模型中心等页面没有按权限隐藏新建/编辑/删除 |
| 没有角色的账号登录后只看到空的概览 | 应该告诉他「你是普通用户，请在业务系统里用 AI 助手」 |
| 没有每个角色的验收用例 | 角色种子、侧栏、路由三处各写一份，容易不一致 |

后端接口基本都已有权限校验（R1 做过收口），本次以种子、前端可见性和按钮为主；发现后端漏校验的一并补上。
