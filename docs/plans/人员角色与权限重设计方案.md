# 人员、角色与权限重设计方案

> 2026-10-17 经用户确认（三点均按建议），按 R1–R4 分批实施。基于 dev 分支（PR #10 之后）的代码现状。
>
> 2026-10-20 导航调整：用户确认恢复原有功能分组，替代 R2 的按人分组方案；角色、权限码、项目范围和接口校验继续保留。下文第二节及第八节 R2/R4 是历史问题与实施记录，当前导航以第四节及[平台定位与架构总览](../01-平台定位与架构总览.md)为准。

## 一、结论

要分，而且分成三类人是对的，但要分清两套完全不同的权限：

1. **平台权限**：谁能在管理端做什么。对象是 **开发人员** 和 **运营人员**（外加一个支撑性的 **平台管理员**）。
2. **调用权限**：终端用户能让 Agent 替自己做什么。对象是 **普通用户**。普通用户不登录管理端，身份来自业务系统（嵌入式对话的 embedToken），权限按业务系统里的角色映射到「能调用哪些业务方法 / Workflow」。

以前混乱的根源，是这两套东西和「谁用哪些页面」都没讲清楚：角色是按功能随手加的，菜单是按技术模块排的，很多页面只要登录就能操作。

## 二、现状问题（代码核对结果）

| 问题 | 证据 |
| --- | --- |
| 5 个内置角色互相重叠，没有「开发人员」 | `sql/initV2.sql` 种子：平台管理员、智能体设计者、项目负责人、运维操作员、审计员。项目负责人≈设计者+发布，运维操作员只是名字像运营 |
| 有死权限码 | `workspace:build:access` / `workspace:operate:access` 有种子但没有任何代码检查；`context:runtime-user:review` 在上下文治理删除后已无用途 |
| 很多页面只校验「已登录」 | 例如调用权限 `/api/tool-acl`（`ControlToolAclController`）任何登录用户都能增删改；项目管理、知识库、模型、Skill、MCP/A2A 等菜单没有 `requiredPermissions` |
| 菜单按技术模块排，和人对不上 | 侧边栏分「智能化改造 / AI 资产 / 运行与治理 / 平台资源 / 实验室」，开发、运营、管理员的入口混在一起；「集成与开放」「身份与权限」等组里混着不同人的工作 |
| 项目级授权有底子但没用起来 | `control_platform_user_role.scope_type` 已支持 `PROJECT`，后端 `PlatformPermissionGrant` 也会判断，但界面和默认角色都按全局授权 |

## 三、目标角色

| 角色 | 对应人群 | 在哪里 | 默认授权范围 |
| --- | --- | --- | --- |
| **开发人员** `DEVELOPER` | Java 接入开发者 | 管理端 + 业务系统代码 | **按项目**授权，只看自己负责的项目 |
| **运营人员** `OPERATOR` | Agent / Workflow 实施和日常运营 | 管理端 | 全局（以后可按项目收窄） |
| **平台管理员** `PLATFORM_ADMIN` | 装平台、管账号和模型的人 | 管理端 | 全局，拥有全部权限 |
| **审计员** `AUDITOR`（可选保留） | 只读检查 | 管理端 | 全局只读 |
| **普通用户**（不是平台角色） | 业务系统里的终端用户 | 嵌入式对话 | 由「调用权限」按业务系统角色控制 |

合并与删除：`AGENT_DESIGNER` 和原 `OPERATOR` 合并为新的「运营人员」；`PROJECT_OWNER` 删除，改为「开发人员/运营人员 + 项目范围」表达。一个人可以同时拥有多个角色。

### 角色能做什么

| 能力 | 开发人员 | 运营人员 | 管理员 |
| --- | --- | --- | --- |
| 项目接入、SDK 凭证、同步诊断 | 读写（本项目） | 只读 | ✓ |
| 业务方法 / HTTP API 维护、变化评审 apply/ignore | 读写（本项目） | 只读 | ✓ |
| 业务方法调试调用 | ✓（本项目） | ✓ | ✓ |
| Workflow 编排、调试、发布 | 只读 | ✓ | ✓ |
| Agent 配置、调试、评测、发布 | 只读 | ✓ | ✓ |
| 嵌入对话、MCP、A2A 开放 | — | ✓ | ✓ |
| 知识库、文件入库、业务索引 | — | ✓ | ✓ |
| 运行中心、Trace、自动化 | 只读（本项目） | ✓ | ✓ |
| 业务用户目录、调用权限 | — | ✓ | ✓ |
| 账号与角色、认证源 | — | — | ✓ |
| 模型中心 | 只读 | 只读 | ✓ |
| 合规擦除、会话保留、运行时用户映射 | — | — | ✓ |
| Skill 包导入/审核/发布 | — | 绑定到 Agent | ✓ |

## 四、目标导航

侧边栏恢复按功能领域分组，每个入口及子项分别按权限过滤，无可见入口的分组隐藏。角色决定可见范围，不再决定菜单归组；不做工作台切换器。

```
智能化改造
  概览
  项目管理        项目列表 / SDK 接入 / 同步诊断 / 页面动作 / 业务索引
AI 资产
  业务能力        Java 业务方法 | HTTP API（含变化评审）
  Workflow
  Agent          配置版本 / 记忆策略 / 嵌入与开放配置
  Skill          标准 Agent Skill 包
  集成与开放      API 市场 / MCP Hub / A2A 互联中心
  知识库          文件 / 检索测试 / 命中分析 / 设置
运行与治理
  自动化中心      定时计划 / 执行历史（独立入口）
  运行中心        对话 / 运行记录与 Trace / 评测
  身份与权限      账号与权限 / 业务用户 / 认证源 / 调用权限 / 运行时用户映射
  合规            跨域数据擦除
平台资源
  模型服务         模型中心 / 模型调试台
个人（侧边栏底部）
  我的记忆 / 退出
```

恢复范围：

- 恢复「集成与开放」全局入口，Agent 自身的开放配置仍归 Agent；恢复「身份与权限」菜单，各子项独立校验权限。
- 保留自动化独立菜单、知识库详情收拢、项目内业务索引和底部个人记忆入口；已退役的实验室及重复入口不恢复。
- 「概览」继续按角色提供快捷入口，不改变已有账号的布局与自定义配置。

## 五、权限码收口

- 继续用「权限码」作为唯一校验单位，角色只是权限码的组合（现有设计正确，保留）。
- 补齐缺失的权限码：`project:read/write`、`capability:review`、`knowledge:read/write`、`model:manage`、`tool-acl:read/manage`、`agent:open:manage`（嵌入/MCP/A2A）。
- 删除死权限码：`workspace:*`、`context:runtime-user:review`。
- 规则：**每个菜单都有 requiredPermissions，每个管理端接口都检查一个权限码**，加一个后端测试扫描未声明权限的控制器。

## 七、已确认

1. 内置角色为开发人员、运营人员、平台管理员，审计员保留为可选只读角色。
2. 开发人员按项目授权，只能看自己负责的项目。
3. 运营人员可以直接发布 Agent / Workflow，不另设发布审批角色。

## 八、实施进度

- R1（PR #11，已合并）：四个内置角色与权限码收口（现见合并升级 `sql/upgrade-20261019-consolidated.sql` 段落 08）；`PlatformConsolePermissionPolicy` 为每个管理端路由声明进入权限；知识库 `/ai/**`、模型 `/model/**` 控制台路由改经 Control 校验后转发；`/api/registry` 只保留签名的 SDK 路由和受登录保护的实例操作；SDK 心跳与下线改为验签。实施中发现的安全问题：线上 Nginx 把 `/ai/`、`/model/` 直接转给 Knowledge、Model，知识库与模型接口无需登录即可访问；部署本批时须把这两条转发改到 Control（18603）。
- R2（PR #12，已合并）：侧边栏按人分为「开发 / 运营 / 平台管理」三组，概览置顶，「我的记忆」留在侧边栏底部的个人菜单。MCP、A2A 归到 Agent 下；业务用户、调用权限归运营的「用户与调用权限」；账号、认证源、运行时用户映射归平台管理的「账号与角色」；API 市场暂放开发组。所有页面路由都声明 `requiredPermissions`（项目接入、Skill、API 市场、MCP、A2A、调用候选检索此前缺失），无权限时进入提示页。按角色的概览卡片放到 R3。
- R3（本批）：概览顶部按角色给出常用入口（开发 / 运营 / 平台管理，纯只读账号显示审计入口）。账号授权编辑器选角色时显示角色说明，开发人员默认「指定项目」，其他角色默认「全部项目」，平台管理员锁定全部项目（后端原已强制）。角色加项目范围的分配能力已存在，本批不改后端。
- R4（本批）：`docs/01-平台定位与架构总览.md` 用户表补上对应平台角色，模块边界改为按人分组的导航表，前端入口改为全部经 Control。
