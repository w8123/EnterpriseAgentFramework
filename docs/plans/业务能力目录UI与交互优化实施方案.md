# 业务能力目录 UI 与交互优化实施方案

关联用户任务 U2（查找、理解业务方法/API）与 U4（识别来源变化）。2026-10-12 用户在截图评审后授权执行以下优化。保留当前玻璃工作台风格、Java/HTTP 两类 owner、调用契约、桌面底部对齐与既有 WIP。

## 目标与实现范围

- 筛选：分类、下拉条件即选即筛；文本通过 Enter/搜索提交，分类/状态切换保留未提交文本，不将其偷偷应用。只修改当前 TAB 的 URL，项目/账号切换继续清理旧上下文。
- 搜索：已提交查询变化后展开命中分类；分类按钮提供可访问选中状态。分类计数相同时收为单一“本页 N 项”，不同才补“分类共 M 项”。所选分类不重复提供“查看此分类”。
- 视觉：共享 `BusinessCapabilityCatalogList` 使用现有 `FilterBar presentation=inline`；在共享项目列表样式 owner 中增加具名目录变体，移除搜索与表体的重复容器边框并收紧间距，保留 40px 控件与内部滚动。
- Java 行：来源收为方法下的轻量信息，名称/说明获得更多宽度；操作性质保留，综合列名改为“状态”且补充真实语义说明。单操作更多菜单改为“归类”，全域仍显示所属项目。
- 刷新：列表与分类共同决定忙态和反馈，部分失败明确说明；HTTP 同步采用分类/筛选行为和共享外观，保留 HTTP 专属概览与字段。

## 分工与验证

1. 查询与两类目录：先补并运行筛选草稿、立即筛选和刷新部分失败的失败测试，再修复 `useCatalogQuery` 与两类目录；保留书签/权限/迟到响应保护。
2. 分类组件：先补搜索后展开、可访问选中状态的失败测试，再修改 `CatalogClassificationSections`；复用原分类关系与说明/重命名。
3. 共享视觉：复用共享筛选与项目表格 owner，在具名目录变体中简化表面，不修改全局主题或项目列表默认视觉。
4. 合并后执行 Capability 相关目标测试、生产构建、相关 UI 守卫、Premium strict 审计与设计上下文 lint。真实浏览器检查 project36 的 Java/API、原问题复现步骤、搜索无结果、分类/详情返回、菜单、键盘、390px 与读取失败重试；不执行业务调用或分类写入。
5. 更新 DESIGN、UX 契约、专项进度与验证记录。截图和开始前 WIP 副本保存在 `output/tasks/catalog-ui-20261012/`。无提交、推送、数据库操作或部署。

## 完成标准

- 输入新关键词后切换分类/状态，文本不消失且未经提交不会改变关键词查询。
- 搜索命中方法直接可见；刷新在分类读取结束前保持忙态，不用完整成功提示掩盖部分失败。
- 首屏只保留主工作面和必要的表格结构；少量数据下空白不再套内层大框，桌面列表与侧栏底部仍对齐。
- 名称/查看打开同一详情，归类与分类说明原入口可达；写权限与业务副作用提示保持。
- 实际运行的测试、构建和浏览器结果记录为证据，受控失败验证与真实业务写入验收分别表达。
